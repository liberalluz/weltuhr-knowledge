## 抽取（步骤 2）

脚本 [`content/tools/extract_skeleton.py`](../tools/extract_skeleton.py)，依赖 `pdfplumber`（内容管线其余脚本仍是纯标准库，这是唯一例外）。

```bash
cd content
python tools/extract_skeleton.py --axis discipline --check
python tools/extract_skeleton.py --axis major --check
```

抽取规则（都对着 PDF 原文核过，不是猜的）：

| 写法 | 含义 | 归类 |
|---|---|---|
| `01 哲学` / `01 学科门类：哲学` | 门类 | `group` |
| `0101 哲学类`（专业轴） | 专业类 | `galaxy` |
| `0101 哲学`（学科轴，码第三位非 5–9） | 一级学科 | `star` |
| `0151 应用伦理*`（学科轴，码第三位 5–9） | 专业学位类别 | `star` + `degree-category` |
| `010101 哲学` / `0502100T 语言学` | 专业（6 位或 7 位码） | `star` |
| 名称末尾 `*` | 仅可授**硕士**专业学位 | 标签 `master-only` |
| 码后缀 `K` / `T` / `TK` | 国家控制布点 / 特设 | 标签 `state-controlled` / `special` |
| `（…）` 括号注释 | 可授学位门类等 | `catalog_note`，**源层专用** |

三处**必须知道的坑**：

1. **「代码第三位从 5 开始」不是「等于 5」**。`0860 生物与医药` / `0861 交通运输` / `0862 风景园林` 的第三位是 6，仍是专业学位类别。只判 `== '5'` 会把它们错记成一级学科，一级学科数虚增 3、学位类别数少 3。
2. **名称会跨页断行**。如 `1007 药学（可授医学、理学学位，同时设专业学位类别，` + 次页 `代码为 1055）`；专业轴同理。脚本按「括号未闭合则续行」拼接，`anomalies` 为空才算过。
3. **专业码有 6 位也有 7 位**。外语类 `0502100T` 起是 7 位，只写 `\d{6}` 会漏 5 条，正好把 845 抽成 840。

## 字段

每个节点：`id` / `axis` / `level_slot` / `official_code` / `name` / `slug` / `scope`(`S0`) / `pack_id`(`skeleton`) / `status`(`live`) / `parent_id` / `tags[]`，必要时 `catalog_note`。

两条口径要写下来，因为**两份规格在这两点上不一致**，本批是按下述方式调的：

- **不存 `path`**。`path-rules.md` P-01 明令任何实体不得存 `path` 快照，`pathOf` 运行期算。校验器只**算出来查重**，不写进 JSON。
- **`id` = `skeleton:` + `<axis>/<official_code>`**。`entity-fields.md` §2 与 `constants.dart` 的 `skeletonNodePrefix` 说前缀是 `skeleton:`；`skeleton-catalog.md` §四说 `id` 由 `<axis>/<official_code>` 构成。两处合起来才既守住实体表、又不让两轴的 `01` / `0101` 撞车（学科 `0101 哲学` 与专业 `0101 哲学类` 同名同码）。
- **`slug` = 官方码小写**（P-05「骨架段的 slug 由 official_code 派生」）。所以 `path` 形如 `major/01/0101/010101`，全 ASCII，天然满足 P-04 的 `^[a-z0-9-]+$`，也不受名称里的全角括号影响。

`catalog_note` 是**源层专用字段**：构建 `skeleton` 包时丢弃（包体只认 `entity-fields.md` §2 的字段集）。留它的理由是目录原文的「可授文学、理学学位」这类信息删了就没了，而骨架升版时要靠它比对。

## 校验（步骤 4）

`--check` 一次跑完，全绿退出码 `0`，任何一条不过即 `1` 并逐条打印：

`official_code` 轴内唯一 · 主父唯一（每节点恰一个 `parent_id`，且父存在）· 无环 · 无孤儿 · 每个 `star` 的父链走到轴根；另加 `id` 全局唯一 · `slug` 正则 · 同父 `slug` 唯一（P-06）· **`path` 全局唯一**（P-07，独立断言，不由 P-06 推出）· 槽位条数对 §五 · `anomalies` 为空。

当前两轴全绿，`anomalies` 均为 `0`。

## 体积（步骤 5）

| 口径 | 实测 | 上限 / 对照 |
|---|---|---|
| 未压缩 JSON | **357,377 B（349 KB）** | §五 按节点折算 `≈1.0 MB × 1,150/3,323 = 346 KB`，吻合 |
| gzip -9 | **24 KB** | §五 的「压缩后 220–300 KB」是**三轴 3,323 节点**的口径，本批只两轴，不宜直接比 |

⚠️ §五 的压缩估算（`1.0 MB → 220–300 KB`，压缩比约 2.9–4.5×）明显保守：JSON 键名高度重复，实测 gzip 到 **14.7×**，brotli 只会更小。**结论按实测记**：两轴远在预算内；三轴齐了再用 brotli 复测一次，届时以实测值回改 §五 的估算区间，不沿用旧数字。

## 已知现象（不是缺陷）

- **学科轴 3 对同名同父**：`1002 临床医学` / `1051 临床医学`、`1003 口腔医学` / `1052 口腔医学`、`1007 药学` / `1055 药学`。一个是一级学科、一个是专业学位类别，码不同、名称相同。P-06 的判据是 `(parent_id, slug)`、明确不比 `name` —— 这正是 `id` 建在官方码上而非名称上的原因。
- **专业轴只有 12 个门类**（无军事学 11），学科轴 14 个。`skeleton-catalog.md` §七 已裁定「两轴门类数不同是正常的，不强行对齐」。
