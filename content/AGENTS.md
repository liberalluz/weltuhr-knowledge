# content —— agent 入口

本目录的**约定、边界与常用命令**。规则细则以项目 `docs/` 为准，**本文件不复制**。

## 路径基准

本文件内所有相对路径**以本目录（`content/`）为基准**。

## 职责边界

- **负责**：知识项与前提边的源数据 · 体系声明 · 声明式题库 · 源摘录（离线可读）· 构建脚本与产物
- **不负责**：审核与 overlay 合并（→ `server/`）· 渲染与匹配逻辑（→ `app/`）· 笔记模板（平台层，不属内容包）

## 关键命令

| 用途 | 命令 |
|---|---|
| 构建全部空间 | `python content/tools/build.py` |
| 构建单个空间 | `python content/tools/build.py <空间>` |
| 确定性检查（不落盘） | `python content/tools/build.py --root <目录> --check` |
| 只校验源数据 | `python content/tools/verify.py --root <目录>` |
| 校验已构建的产出 | `python content/tools/verify.py --pack <pack.json>` |
| fixtures 回归 | `python content/tools/verify.py --suite` |

命令在**仓根**执行。取值域与 issue code 见 [`tools/README.md`](tools/README.md)。

## 红线

- **`Item.id` 必须与版本无关**：稳定 id 一旦发布不得改写。若 id 带版本号，升级后所有已学事件都会指向旧 id，迁移与下线机制全部失效。
- **一空间一包**：空间边界按三判据裁定（独立 `⪯` · 独立版本 · 三层结构齐全），缺一条则降为上位空间内的「域」，不得独立成包。
- **生成物不入库**：`dist/` 被 `.gitignore`，须本地构建。源数据（json / md）体积小，**入库**。
- **笔记模板不进包**：pack 只提供六要件内容，模板在平台层声明。模板入包会让「零核心代码改动接入新空间」失效。
- **源摘录不得内嵌无许可内容**：每条摘录必须带出处（页码 / URL）与许可标记；`excerpts` 段是部分扩大 schema 冻结范围的唯一正当理由，但须逐条可追溯。
- **不得代写「不可外化」格**：六要件三态中的「不可外化」是合法状态，不是缺陷；构建与校验都不得把它当缺失处理，也不得由模型补写。
- **体系必须是 `⪯` 的线性扩展**：前置必须排在后继之前。逆序不禁止，但须算出逆序数随包声明，供 Planner 显式展示代价。
