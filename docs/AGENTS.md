# docs —— agent 入口

本目录的**约定、边界与判据**。目录分工以 [`README.md`](README.md) §一 为准，**本文件不复制**。

## 路径基准

本文件内所有相对路径**以本目录（`docs/`）为基准**。

## 职责边界

- **负责**：设计规格与横切表（`specs/`）· 上游论证（`intent/`）· 未认定的候选（`ideas/`）· 操作手册（`runbooks/`）· 架构决策（`decisions/`）
- **不负责**：客户端实现约定（→ `app/AGENTS.md`）· 服务端实现约定（→ `server/AGENTS.md`）· 内容包与构建（→ `content/AGENTS.md`）· 部署与 CI（→ `infra/AGENTS.md`）

## 落点判据

| 要写的是 | 落哪 |
|---|---|
| 是什么 / 为什么 | `specs/` 或 `decisions/` |
| 多少次 / 哪些值 | `specs/` |
| 还没认定的想做什么 | `ideas/`（**不得作为实施依据**，见该目录 `README.md`） |
| 怎么操作 | `runbooks/` |
| 对外交付、需签字、需版号 | **不在本仓** —— `ADR-0009` 起仓外托管 |

## 红线

- **记录类不追溯补录**。`DPMR` / `STR` 记录的是「当时确实如此」，事后补写会让证据退化为叙述。判据：这份文档在**记录一次已发生的事**，还是在**描述当前应当如此**？前者不补，后者可补。
- **基线只在 `SCMP` 登记**。别处不得再留一份可改的基线表 —— 复制就有两份事实源，两份就一定会不同步。
- **活文档不设版号**。`specs/` `intent/` `ideas/` `runbooks/` `decisions/` 的更新时间以 `git log` 为准，**不手写「最后更新」头** —— 手写头会变成第二份会过期的记录。
- **版号历史表按版号降序，新行插表首**。`specs/` 参与版号自洽的四份（`SCMP` / `STD` / `STP` / `SDD`）与 `SDP` 的「历史 / 修订历史」表只有一种读法：**从上到下越来越旧**。补录旧版号时**按版号插到它该在的位置**，不追加末尾 —— 「追加表尾」与「插在某个锚点前」两种习惯混用，会把表搅成交错序（2026-10-23 之前六份表即如此，`SCMP` 的 `v0.30.0` 行还留着一句「留待单独一笔整表排序」）。判据由 `D2` 守（相邻两行必须严格降序，相等也报）。
- **引用不复制**。同一规则只在唯一权威处展开，其余位置写「见 XX」。数值只在 `specs/` 维护。
- **骨架文件的填充时点写在文件头**，不得因为「顺手能写」就提前填 —— 时点没到之前写出来的内容只是猜测，而且会被下游当成已定事实。
- **验收必须可观测**。写不出可观测断言的条目，说明该条没想清楚；不得以「实现里写了」充当验收。
- **旧实体名残留只按标识符位置判，不按字面量 `grep` 判**。`ADR-0005` / `0007` 换本体后，「旧实体零残留」这类判据（如 `B13a` 出口的 `Item`）只看这几种形态：`class Item` · `Item(` · `: Item` · `<Item>` · `as Item`。**注释、文档串、lint 夹具里的旧名不计** —— 它们记的是「这个类曾经存在」或「为什么不再用它」，正是要留的来历；按字面量计 0 等于先把历史删干净，而删完之后没人知道 `LearnableNode` 为什么叫这个名字。判「现时陈述 vs 历史叙述」沿用上一条的同一把尺：**这句话描述的是现在跑的代码，还是当时有过的东西**。⚠️ 现时陈述改，历史叙述不改 —— 但**跨行叙述要看上下文**（`/// 与 `Item` 没有关系` 承接上一行的「旧名把…写进了类型名」，是历史）。

## 译本规范

**中文是唯一事实源**，英文是默认展示语言。**库内文档**一律 `中文原文 + 各语言译本`，译本不得成为第二事实源；**对外层**另立一套口径 —— 权威是英文，见下表「对外层」。

| 项 | 规则 |
|---|---|
| 命名 | `<原名>.<lang>.md` —— `README.zh-CN.md` · `SDP-软件开发计划.en.md`。**原文保留 `<原名>.md`**，不加后缀 |
| 语言码 | `zh-CN` `en` `de` `it` `ja` `fr`（BCP 47）。**简体固定写 `zh-CN`，不写裸 `zh`** —— `zh` 是宏语言码、不区分简繁；将来加繁体用 `zh-TW`。取值与 `.swe-init.json` 的 `docsLocale.supported` 一致 |
| 对外层 | **根 [`README.md`](../README.md) 及仓根五份译文**：权威 = **英文** `README.md`（首页渲染，账本 `docsLocale.external = en`），`README.zh-CN.md` 是译文之一、不是原文。**其余三份对外文件不出译文**：[`.github/CONTRIBUTING.md`](../.github/CONTRIBUTING.md)（新 issue / PR 界面自动链接）· [`.github/SECURITY.md`](../.github/SECURITY.md)（Security 页 policy）· [`.github/CONTRIBUTING.ai.md`](../.github/CONTRIBUTING.ai.md)（AI 参与准入）—— 治理、安全与准入三处措辞不一致会引发歧义 |
| 落点 | 译本**与权威版同目录**：根 README 的五份译文即在仓根；库内文档的译本与其**中文原文**同目录。**`.github/` 下不出译文**（见上「对外层」） |
| 切换条 | `English · 简体中文 · Deutsch · Italiano · 日本語 · Français` 固定顺序，**当前语言加粗不设链接**。**对外层置于 `# 标题` 之前**（访客第一眼看到）；**库内文档置于 `# 标题` 之下** |
| 溯源行 | 库内译本：头部写 `> Translation of <中文原文链接> · <日期> · the Chinese version is authoritative.`，**不写 commit sha** —— 提交前不可知，写了必然立刻误报。对外层：头部写 `> 以根 README.md @ <sha> 为准` 的等价措辞，**sha 必写**；它指**所据英文版的提交**、不是本笔提交，故提交前已知。⚠️ 两层相反是刻意设计，不是笔误 |
| 跟译 | **改根 `README.md` ⇒ 同一 PR 内同步五份译文**；确实只跟得动一部分时，至少把 `@ <sha>` 前移并在 PR 正文列出未跟的段落。库内文档**不承诺逐轮同步**，靠溯源行让读者自行判断新旧 |
| 链接 | 目标已有译本 ⇒ 指向同名译本；目标尚无译本 ⇒ 指向中文原文。**不指向其他译本** |
| 不译 | `AGENTS.md`（两套语言 = 两套规则源）· `LICENSE` · `NOTICE`（法律文本） |
| 完整性 | **中文原文不得删除，译本不得单独存在** —— `check_s0` 只判前缀存在，删了中文会静默通过 |

**已落译本**：仓根 `README.zh-CN.md` / `README.de.md` / `README.it.md` / `README.ja.md` / `README.fr.md` 五份，**全部译自英文 [`README.md`](../README.md)**，溯源行带 `@ <sha>`；**`.github/` 三份不出译文**（见上「对外层」）。`docs/` 下 **45 份**（`find docs -name '*.md'` 共 46 份，减 1 份不译的 `AGENTS.md`）的译本**等首个版本发布后统一做** —— 那一批走**库内口径**：中文是事实源、溯源行以中文原文为准、不写 sha。
