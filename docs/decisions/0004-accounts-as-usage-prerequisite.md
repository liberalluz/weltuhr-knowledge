# ADR-0004 · 账号作为使用前提

- **状态**：已接受
- **日期**：2026-10-18
- **决策人**：liberal
- **覆盖范围**：[`ADR-0002`](0002-dev-order-vertical-slice.md) 中「服务端不在 `v0.1.0` 关键路径」一节

## 背景

账号系统此前**从未进入需求基线**：`docs/specs/` 八份规格、`not-list`、`SRS` 全量 grep「账号 / 登录 / 认证 / 注册 / 用户体系 / 凭据」零命中；`server/` 只有 `README.md` 与 `AGENTS.md`。`ADR-0002` 明文写「Windows 单机首期不依赖服务端」，并在 `SDP` §4.4 落成「`P2` / `P3` / `P4` 都不在 `v0.1.0` 关键路径」。

讨论中出现过一个方向性错误：先把「没规划」读成「可以不做」，并据此提出「把『无账号』写进 `NOT` 清单」。该方向被否决 —— 账号承担着 **同步的正确性前提**（双向合并必须先能回答「这两份事件流是否属于同一个人」），不是可选装饰。

随后确认产品方向：**要用产品必须先登录**。

## 决策

### 1. 账号是使用前提，但登录后离线完整（B1）

未登录不得进入主界面；登录一次之后，五档视图、学一项、写事件、看进度全部不依赖网络。

**为什么门槛设在首次而不是每次**：会话采用标准 JWT（`access` 短 + `refresh` 长且滚动，见 `ACC-010` / `C-45` / `C-46`）。「每次启动都联网校验」会让用户在无网环境打不开自己的知识库，对一个本地优先的学习工具是致命体验。评估过「长期有效凭据」（B2），代价是要另造一套凭据安全机制（设备绑定、被盗撤销、丢失注销），判断不值得 —— 90 天滚动已把「需要重新登录」压到「一个季度未使用 + 恰好断网」这一格。

**为什么否掉「无门槛、仅引导登录」**：这是纯产品取舍。技术上前者更省事、且无审核风险，但不符合已确认的产品方向。本 ADR 记录的是**决策**，不是「技术上最优解」。

### 2. `userId` 在 `v0.1.0` 就进事件 schema

事件公共信封加 `userId`（`ACC-013`），`v0.1.0` 取本地默认值。**不放进 `hlc`** —— 前者定归属，后者定顺序。

**理由不可协商**：`R3` / `X-04` 规定事件只 append、不得改写。若等账号上线再加字段，只有两条路 —— 迁移全部历史事件（违反 `R3`），或永久保留「缺字段视为匿名」的分支（永久分叉）。这是全案唯一「现在不做以后更贵」的一条。

### 3. 服务端最小集前移到 `P1`，增量同步仍在 `P2`

| 内容 | 原归属 | 新归属 |
|---|---|---|
| 账号（`account` / `session` 两表 + 注册 / 登录 / 刷新 / 登出 四端点 + 注册 / 登录 两屏） | `v0.2.0` | **`v0.1.0`** |
| 邮箱验证、找回、多设备管理、`identity` 完整分层 | `v0.2.0` | `v0.2.0`（不变） |
| 手机 / Apple 渠道 | `v0.2.1` / `v0.2.2` | 不变 |
| 增量同步（[`SYNC`](../specs/SYNC-sync.md)） | `v1.1.0` | **`v0.2.0`** |
| 双向合并算法、私有化 | `v1.1.0` | 不变 |

**同步为什么不一起提前到 `v0.1.0`**：`v0.1.0` 的出口是「五动作闭环」，只需要「能登录」，不需要把事件搬到另一台设备。同步提前到 `v0.2.0` 是因为那时账号已有真实数据、且服务端表结构已存在，加增量是同一批基础设施上的加量；留到 `v1.1.0` 则会使用户在上架版里只得到「备份」，账号价值打折。

### 4. `v0.1.0` 不做邮箱验证与找回（`ACC-007`）

此时云端尚无数据（同步在 `v0.2.0`），「丢号」不等于丢数据。省掉邮件服务商这个 `P1` 外部依赖，并消灭「收不到验证邮件就彻底进不去」这一失败模式。注册页须明示「忘记密码将无法找回」，不写即欺骗用户。

### 5. `ACC` 与 `SYNC` 分两份域文件

`ACC` 回答「谁是谁」，`SYNC` 回答「怎么搬」。混写会让一份文档同时装产品规则与协议细节，与 `GOV` 曾被要求承载传输层时的问题相同。

## 后果

1. **`ADR-0002` 的「服务端不在关键路径」在 `P1` 范围内失效**。本 ADR 不修改 `ADR-0002` 原文 —— ADR 记录的是「当时为什么这么定」，改原文会让那个理由消失。两者靠本文件的「覆盖范围」字段建立关系。
2. **`SDP` §1 的边界表述与 §4.4 关键路径须重排**，`P1` 出口由「五动作闭环」改为「登录后五动作闭环」。
3. **新增风险**：邮件服务商依赖（已由决策 4 推迟到 `v0.2.0`）· Apple 指南 5.1.1(v) 审核风险（核心功能不依赖账号却强制登录，需在审核说明里把「多设备同步」写进核心功能）· `R-13` 从「只卡 `B8` 签名」扩为「同时卡 Apple 登录渠道」。
4. **`v0.1.0` 的验收链条变长**：登录需要真实服务端，沙箱内跑不了，交付验证必须依赖部署环境。
5. **隐私政策与账号删除入口**因收集邮箱而提前，不再等到 `P3`。
