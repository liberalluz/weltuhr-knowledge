# ADR-0003 · 宇宙视图的径向语义与三处通道判据

- **状态**：已接受
- **日期**：2026-10-17
- **决策人**：liberal

## 背景

`B2` 收尾时，`STD` §五 挂着三条「`B3` 前定」的待办：`r` 的复合轴没定义、「主取值」没有承载位、「指向未知」没有视觉表达；另有 `φ` 的深度归一化缺口径。四者都指向同一件事 —— **`SPEC-VIEW-002` 只说「三维坐标各承载一个维度」，但没说 `r` 是哪一维**。

`SPEC-VIEW-002` 原文写「`r` = 复合轴（7 段径向分层）」。**全仓没有第二处解释「复合」由哪几维合成**：`SRS` 只重复了一句「各承载一个维度」，`channel-table` 管通道不管坐标。因此这不是「查一下就能补」的缺口，而是必须重新裁定。

裁定前做了三组实算（α 包 150 项 / 170 边，`content/python/dist/pack.json`），结论见各决策。

## 决策

### 1. `r` = 域带，段数 = 空间域数（替换「7 段」）

同一空间内按 `manifest.domainIds` 顺序等分，`r = (域序号 + 0.5) / 域数`（`C-30` 的公式不变，只把常量 7 换成域数）。

**Z0 边界**：跨空间时先按 `manifest.order` 分层、层内再分域，同一空间不跨层。
**Z2 起**：`r` 恒等于该域带，不再分担定位职责 —— 域即根，属正常退化，不是缺陷。

**理由（两条实算）**

1. **α 包里没有任何单维能分 7 段**：`layer` 3 值（143/4/3）· `type` 4 值（78/63/6/3）· 连接度 4 值（1–4）· `k` 4 个取值 · `domainId` 10 值（15×10，完美均衡）。
2. **任何二维交叉最多 6 个非空格**：`type×tacit`、`layer×tacit`、`type×layer` 都是 6，且 `type×layer` 前两格占 137/150（89%）—— 映射到径向会挤成两团、其余四段细如发丝。

而 `Item` 九个字段里，只剩 `type` 与 `domainId` 未被任何通道占用（`layer`→形态 · `requirements`→亮度/虚实 · 连接度→大小 · `sixAxis`→颜色/`θ` · 边→边样式 · `mastery`→轨道环 · SRS→脉动）。`type` 又与虚实通道**完全共线**（见决策 2），故只剩「域」。

**顺带的好处**：三个坐标变成正交且语义清晰 —— `r` = 哪个域（容器）· `θ` = 六轴（分类）· `φ` = 前置深度（顺序）。

### 2. 虚实判据 = 不可外化格 ≥ 3（`C-34`）

**理由**：α 包的不可外化只有三档，中间没有别的情况 ——

| 不可外化格 | 项数 | 组合 |
|---|---|---|
| 0 | 37（24.7%） | 无 |
| 1 | 110（73.3%） | **恒为 `tacit`** |
| 3 | 3（2.0%） | `boundary + proposition + tacit` |

`≥ 1` 会让 113 项（75%）变虚，虚化从「例外」变成「常态」，通道失去区分力；`≥ 2` 与 `≥ 3` 在这份数据上**完全等价**（2 格的项不存在）；取 3 是唯一配得上「高比例」措辞、且能圈出群体的值。

**语义验证**：命中的 3 项是「组合优于继承」「宽恕与许可（EAFP/LBYL）」「线程 / 进程 / 协程选型」—— 三件公认靠经验判断、写不成条文的事。

**同时发现一处共线**：这 3 项正好是 `type = tacit` 的全部（两处标注一字不差）。故 `type` **不得再占用其它通道**，否则同一个事实会被表达两次。

**已知代价**：通道在 α 包上只亮 3 个点（2%）。这是内容侧标注密度问题（`tacit` 格 73% 的项都有），登记给内容侧 v0.2，**不得靠放松阈值解决**。

### 3. 新增 `Item.primaryAxis`（第 4 次扩 schema）

`channel-table` §一 #5 明文要求「按主取值着色，**声明式指定，不按优先级猜**」，而 `sixAxis` 是「六键各单值」的 object，没有主从关系。

| 被否方案 | 为什么否 |
|---|---|
| 用 `manifest.sixAxis` 的轴序，首轴为主 | 「取顺序第一个」正是规格排除的「按优先级猜」；且 `manifest.sixAxis` 是空间级声明，不是项级 |
| 运行时按「该轴取值在空间内的稀有度」推 | 改内容就换色 —— 同一项颜色不稳定，与「位置即语义」要求的确定性相冲 |

**代价如实记录**：这是第 4 次扩 schema，而 `SPEC-VIEW-025` 已把第 3 次称作「扩 schema 的临界点」。但颜色与 `θ` 扇区都等这一个字段，不给它，宇宙视图只能继续用域序号占位（当前 `scene.dart` 的状态）。须登记为 `PACK` 的 B 级变更，内容侧补值。

### 4. `φ` 的径向位置 = 累计项数分位（**改掉了「分段折叠」**）

`SPEC-VIEW-002` 只写「`φ` 越深越靠外」，没写怎么归一。α 包的 `φ` 铺到 **63 层**、0 层只 3 项，等距展开会把层间距压到 `~0.025`，深层必然粘连。

**原方案是分段折叠（0–9 展开、≥10 收成一条「深层带」），实测否掉了它**：`φ ≥ 10` 的层装了 **126 项（84%）** —— 把 84% 的项挤进一条细带，折叠本身就是新的粘连源。任何一个固定阈值都救不了，因为尾部 54 层平均每层只 2.3 项。

**改为**：径向位置取**该层起始项的累计分位**，`r_φ = 累计在前项数 / 总项数`。半径正比于项数，密度自然均匀；0 层那 3 项落在 `r_φ ∈ [0, 0.02)`，符合「根在中心」；也不需要「另有 N 层」这类计数。

> 这条与 `SPEC-VIEW-008`（深链空间首屏只到 `φ=2`）不冲突：那条管的是**树的展开深度**，这条管**宇宙的径向位置**。

### 5. 「指向未知」沿用 `SPEC-VIEW-007` 的黑洞，不新增线型

`channel-table` §一 #6 把「弱依赖」与「指向未知」都记虚线，但后者端点不在册、画不出线（170 条边里 3 条被跳过）。**宇宙视图沿用树视图已有的黑洞**：缺失端画虚线占位节点（父位取「指向它的边的源点质心」），边指向它。

理由：`VIEW-007` 已经把「有痕迹无实体」做成了虚线占位 + 质心定位；跨视图沿用同一套视觉语言，比发明第三种画法省掉一次「一通道一维度」的豁免申请。

## 影响

- `SPEC-VIEW-002` **原地修订**（原句保留，表下加修订注记，不改编号、不新增 `SPEC`）—— `SPEC` 总数仍 171，`SRS` 的 128/81 切片计数不受影响。
- `channel-table` §一 #4 / #5 / #6 的判据补明文（本表是通道映射的唯一权威处）。
- `entity-fields` `Item.primaryAxis`；`constants` 新增 `C-34`。
- `STD` §五 第 8–10 项（主取值缺承载位 / 指向未知无视觉 / `φ` 无归一）可标闭环。
- **内容侧待办**：包 schema 加 `primaryAxis`（`PACK` B 级变更）；提高默会类标注密度（当前 2%，`tacit` 格标注过宽）。
- **未动**：`θ` 扇区的递归区间分割口径（`VIEW-002` 原文已写「含轴内递归区间分割」，`B3` 实现时细化）；窗口尺寸自适应（归 `ADR-0002` 修订二）。

## 修订 · 2026-10-17（`B3` 笔 1 实施时）

### 1. §决策 3 的落地形态：项级必填 → 空间默认 + 项级覆盖

原文写 `Item.primaryAxis` **必填**。实施时发现 α 包 150 项**每一项都是双轴**（`ability` 与 `subject` 各 150/150），没有唯一候选 ⇒「必填」会把内容侧卡死，而临时拿某个轴顶替正是规格排除的「按优先级猜」。

现改为：`manifest.defaultPrimaryAxis`（**空间级明文声明**，与 `accent` / `order` 同级）+ `Item.primaryAxis`（可选覆盖）。两者都缺 ⇒ 扇区取越界哨兵 `sectorCount`、颜色落「未声明」，**不塞进任何一个轴**。α 包取 `ability` —— `subject` 在全空间只有一个取值，用它做扇区等于零信息，这不是偏好而是数据决定的。

### 2. §决策 4 的措辞纠错：`φ` 是**轴向**归一，不是径向

原文与 `VIEW-002` 的注记把 `φ` 的归一写成「径向位置」，**错了**：径向已被 `r` 的域带占用（`projection.dart` 里 `φ` 落 `worldY`）。量名改为 `φ01`（0 = 第一层起点，1 = 末层末端）。裁定内容不变。

### 3. 两处实施时才明确的细节（原文未定）

| 项 | 实施处置 |
|---|---|
| **轴内递归区间分割**（`VIEW-002`「含轴内递归区间分割」） | 需要**各轴的取值序列**，而包与清单都只有取值、没有序列 ⇒ `sectorFraction01` 落 `0`；补字段后再细化（归笔 2） |
| **占位节点的位置** | 取源点位置 + `C-36`（`0.02` 径向外移）—— 不偏移会与源点完全重合，点压在点上看不出缺东西。最终表现（虚线圈 / 引出线）归笔 2 |

## 修订 · 2026-10-17（`B3` 笔 2 实测反馈后）

实测截图暴露两件事：**150 个点挤在一条线上**（`sectorFraction01` 恒 0），且**整团点缩在中间偏下一小块、最下一排被窗口切掉**（写死的 `focal 1.6 / distance 3` 两头都不对）。

### 1. 扇区内的轴值序 = **首次出现顺序**

`VIEW-002` 写「`θ` 含轴内递归区间分割」，但包里只有轴取值、没有取值序列。裁定：**按 `items` 顺序首次出现的次序**（α 包 `ability` 恰好是「基础语法 → 类型与对象 → 控制流 → 抽象 → 数据建模 → 迭代与生成 → 工程实践 → 类型系统 → 并发」，本身即语义序）。

- 不选「`manifest` 新增 `axisValues` 数组」：要改 schema + 内容 + 构建脚本，而现有数据已隐含同等信息
- 不选「字符串码位序」：中文按码位排出来的顺序与「先学什么」无关，扇区里点的位置会显得随机
- 位置取段中线 `(i + 0.5) / n`：取段端点会压在扇区边界上，相邻两值看起来像跨了轴

### 2. 取景 = **按世界半径自适应焦距**（`C-38`）

写死一组的毛病不是「偏一点」，是**两头都不对**：可能太小（全塌成一点）也可能超出（被裁）。改为按场景世界半径 `R = √(r² + (φ01·phiHeight)²)` 解出 `focal = 目标半径 × distance / R`。

- **只动 `focal` 不动 `distance`**：距离变了透视强度就变，同一个空间在不同窗口下会看到不同的近大远小
- **按世界坐标算，不按投影包围盒算**：场景每帧自转，投影包围盒随 yaw 变化 ⇒ 每帧焦距不同 ⇒ 画面「呼吸」
- 允许半径 = 视口短边 × `C-38`（0.46，两侧合计 92%，留 8% 给点半径与线端）

## 修订 · 2026-10-18（`B12` 首笔前 · `r` 的几何落点改沿旋臂弧长）

> **本节是解释段的细化，不是决策变更**：`r` 的**语义**（域带 · 段数 = 域数 · 分位公式 `(段序号 + 0.5) / 段数`）一字未动，`θ` / `φ` 两个通道也未动。改的只是「这个分位在屏幕上落在哪条曲线上」。

### 1. 原状与改因

原文（§决策 1）只写了径向分位 `r = (域序号 + 0.5) / 域数`，没写这个分位在屏幕上走**直线半径**还是**曲线**。`B3` 实现时取了直线半径 —— 于是 `Z1` 里 8–10 条域带是**同心环**。

同心环有两个问题：

| 问题 | 事实 |
|---|---|
| **形态错** | 同心环是「行星轨道 / 原子模型」的意象。真实星系是**旋涡**：核球 + 两条从核球甩出的旋臂。用户在终端看到的第一眼就判「这不是星系」 |
| **在没有旋臂时反而更糟** | `english` / `german` 每域 0 项以外的项全落一轴 ⇒ 只占 60° 扇区，同心环在该楔形里几乎重合，域与域分不开（现状截图即如此） |

改因是用户 2026-10-18 定的方向原则：**真实天体形态优先**，工程妥协只在「可点性 ≥ 24px · 确定性（禁随机，`hash` 定）· `VIEW-003` 六通道不许新开」三条硬约束下才允许，且必须显式标注为妥协。

### 2. 新落点：沿旋臂的弧长位置

- **形态**：核球 + **两条**对数螺线旋臂，`r(θ) = r₀·e^(bθ)`，`b = tan(螺距)`（螺距进 `C-58`）。盘倾角进 `C-59`。⚠️ **原文此处写的是 `b = 1 / tan(螺距)`，因子反了**（2026-10-18 `V-1c` 落地时发现，勘误全文见 [`constants.md`](../specs/constants.md) `C-58` 行下的注）：按 `1/tan(15°) = 3.73` 算，盘半径比 12.5 只转 `0.68 rad`（几根近乎笔直的径向短刺），`Z1` 根本不成旋涡。
- **域 `i` 的落点** = 该域在旋臂弧长上的**中点**：把整条臂按域数 `n` 等分，取第 `i` 段的中点。分位仍是 `(i + 0.5) / n` —— 与 `C-30` 的公式完全一致，只是「弧长的 x%」而非「半径的 x%」。
- **两条臂各一个点**，关于核球中心对称。同一域因此有**两个**可见落点，但它们是**同一个域的两个投影**，拾取命中任一个都进 `Z2`。

### 3. 为什么不违反「一通道一维度」（`X-02`）

`r` 仍只承载「哪个域」这一个维度。弧长与半径是一一对应的参数化（同一分位、同一域），不构成第二个语义。⚠️ **不得**借这个改动给 `r` 加任何新含义（如「越靠外越难」），否则就是私开通道。

### 4. 代价（如实记录）

1. **域间距不再等距**：弧长等分 ⇒ 半径上内密外疏（对数螺线本身如此）。`pick` 的最近邻判定要按**弧长参数**算，不能按半径差。
2. **`Z2` 起 `r` 退化为「该段弧的中点」**：原文「`Z2` 起 `r` 恒等于该域带，不再分担定位职责」仍然成立 —— 退化的含义不变，只是那条带现在是弧段而非扇环。
3. **`fitCameraToViewport` 不受影响**：它按世界包围盒算，与落点走直线还是曲线无关。
4. **旋臂是让步的视觉层**：真实旋臂是**密度波**（图案速度 ≠ 物质速度）。项目把域点钉在旋臂上，等价于「跟图案速度」，也就是刚体等角速度 —— 这与 §决策 1 的「段数 = 域数」不冲突，但须在 `VIEW-037` 写明是让步。

## 修订 · 2026-10-18（`V-1d` 落地时 · `φ` 在 `Z2` 落成「云内半径」）

`VIEW-038` 把 `Z2` 从「项投影近景」改成「一朵分子云 + 亮结 + 跨域出口」。这一改让 §决策 4 的 `φ` 落法在 `Z2` 不再成立 —— 与上一节的「`r` 改沿弧长」不同，那次只动 `r` 的**几何**，这次要动 `φ` 的**落法**，所以单列一节说明为什么它不算改决策。

### 1. 原状与改因

§决策 4 的式子是 `r_φ = 累计在前项数 / 总项数`，`§修订 2026-10-17 §2` 已把它的措辞纠正为「**轴向**归一，不是径向」。`Z0` / `Z1` 都在**侧看盘面**，轴向高度看得见，那个式子成立。

`Z2` 是**正对云面**看一朵云。此时「轴向高度」在屏幕上是一条**竖线** —— 按原落法，一个域的项会全部压在云心那条竖直细线上，域的形状信息一点不剩。这不是取值不对，是**该通道在正对视角下没有承载面**。

### 2. 改法：同一个式子，换分母

`φ` 的语义**不变**（仍是累计项数分位，§决策 4 的结论一字不动）。改的是它落在哪：正对云面时落到**云内半径**上，`r = 云半径 × (0.12 + 0.74 × 域内分位)`（`C-63` 定云半径，`0.12` / `0.86` 是内缘与外缘留白）。「越深越靠外」的原文表述照样成立 —— 只是「外」从「盘厚方向」变成「云半径方向」。

**分母必须跟着换。** 若沿用全局分母（`累计在前 / 总项数`），python 有 10 个域，单个域只占累计区间的约 1/10，第 3 个域的项会全挤在 `r ∈ [0.2, 0.3)` 的窄环里 —— 云半径留到 `0.86`，实际只用掉一成。改为**域内口径**：`r_φ' = 域内累计在前项数 / 域内项数`。

**代价如实记录**：`Z2` 的半径与 `Z0` / `Z1` 的半径**不是同一把尺子**，跨档读数不可比。可接受 —— 三档本来就是三套几何（`VIEW-036`–`040`），跨档唯一共享的通道是 `θ`。

### 3. 项数不得变成第二条通道

云内粒子总数固定 `C-62 = 240`，**不跟项数走**。半径的取值分布、点密度已经随项数变化；粒子数若也随项数变，就成了第三条「项数」通道 —— `X-02` 一通道一维度。粒子只表「这是一朵云」这个物理形态。

### 4. 亮结 = `⪯` 子树，与 `Z1` 暗斑共用一份实现

`Z1` 的暗斑与 `Z2` 的亮结是同一件事（域内 `⪯` 子树）在两个尺度上的画法。两处各写一遍**不会有任何东西变红**（`R-08`）⇒ 划分收归 `core/graph/subtrees.dart` 的 `subtreesInDomain()`，`spiral_map.dart` 原先私有的 `_rootsOf` 与 `prereq` map 已删除。

**缺口如实登记**：多前置的项会**同时属于两棵子树**（当前三包都是链 / 树，不触发），故「两棵子树成员数之和大于域内项数」是如实结果、不是数错。

`isSingle`（单项子树）在界面上的落点：直接进 `Z4`，跳过 `Z3` —— 一个只有一项的子树没有「共面轨道行星」可看。

### 5. 跨域边画出口标记、不画断线

`Z2` 只画一朵云，跨域边有一端在云外。`NebulaDrawTarget` 只暴露 `thread`（域内线）与 `exitMark`（云缘朝外箭头），**没有通用 `line`** —— 这是 `R-08` 的正面用法：形状挡得住「改」，也挡得住「加」。

出口按目标域的出现顺序均分云缘（`(i + 0.5) / n`），再叠一个 hash 定死的微抖动（±0.03 rad，`_exitAngleJitter = 0.06`）。**抖动是让步**：真实分子云没有「出口」，均分不抖会像刻度盘。

出口文案目前退成末段域名（`→ 进入 vocab`）：包里没有 `Domain` 实体，〈动词形态〉无数据 —— 与 `VIEW-018` 的中文域名同一个 `PACK` 缺口，不假造。

### 6. 代价（如实记录）

1. **跨档半径不可比**（见 §2）。
2. **同扇区项会在云缘形成密集弧**：`θ` 仍走六轴扇区，同扇区的项沿同一角向排列 ⇒ 项多的扇区在云缘堆成一段密弧。已接受，**不**加角度扰动 —— 扰动会破坏「`θ` = 六轴」的读数，那是比密度更硬的判据。
3. **拾取次序是「容器优先」**：先判亮结（`domainMarkMinTapDiameter` 的 24 px 可点**直径**，`VIEW-037`），未中再判项（8 px）。反过来会让亮结中心那颗星永远点不中。⚠️ 原文此处把 24 写在 `C-44` 名下 —— `C-44` 是点星的 8 px，24 是另一个常量，`V-1e` 时改正。
4. **云心可点**：`Z0` / `Z1` / `Z2` 三处标注层与 `B3` 的 ⑤「焦点星」占位都压在画布上，原先只有「没人点那里」保着。`Z2` 第一次把可点对象放到屏幕正中就暴露了它（`STR` 轮次 `R7` 记为已修的静默缺陷）。现三处一并包 `IgnorePointer`。

## 修订 · 2026-10-18（`V-1e` 落地时 · `Z3` 里 `θ` 与 `r` 同时退化）

### 1. 原状与改因

前面三档至少保住一个通道：`Z0` 保 `r`（域带）、`Z1` 保 `r` 与 `θ`、`Z2` 保 `θ`（`φ` 改落云内半径）。

`Z3` 画的是**一个恒星系**（`VIEW-039`：一条 `⪯` 链），两个通道同时失去意义：

- **`r` 无处落**：整档只有一个域，没有「相邻域」可比 —— 域带在这里退化成「整个画面就是一个域」。
- **`θ` 无处落**：行星的方位角由「同层均分 + 哈希抖动」定，与 `primaryAxis` 无关。硬把六轴搬进来，等于宣称「这颗行星在某个轴上有个位置」—— 而那颗行星是**一项知识**，它的轴属性属于 `Z1` / `Z2` 的读数，不是它在轨道上的位置。

这是 `Z0`–`Z3` 里**第一次两个通道一起退化**。

### 2. 谁承载语义：只剩 `φ`

`φ` = 相对恒星的层号 → **第几条轨道**（`VIEW-039` 正文：「轨道半径映射 `φ`」）。

恒星自己 `φ = 0`（它在中心、没有轨道）；层号从恒星出发按**最短路径**算（BFS），所以一颗行星**只归一层** —— 这是与 `subtreesInDomain()` 那处已知缺口（多前置的项会同时属于两棵子树）不同的一点：那里划的是集合，这里定的是位置。

### 3. 为什么不违反「一通道一维度」（`X-02`）

`φ` 在这一档只承载**一个**维度（层号 → 轨道序号），没有兼职。

`θ` / `r` 是**退化**，不是**复用** —— 它们不画任何东西。这与 `Z2` 把 `φ` 从「轴向高度」改落「云内半径」是同一个动作的另一面：那里换的是**落法**，这里取消的是**通道本身**。

### 4. 代价（如实记录）

1. **这一档不能靠位置读轴与域**。`Z0`/`Z1` 读「哪个域大、哪个域在哪个方向」，`Z2` 读「这个域里项落在哪个扇区」，`Z3` 只读「这条链有多深、谁先谁后」。规格没有要求更多 —— 但读者若带着前三档的习惯进来，会发现「方向」这一维突然没信息了。
2. **跨档 `φ` 不可比**（第三次记这条）：`Z2` 的 `φ` 是**累计项数分位**（域内口径），`Z3` 的 `φ` 是**层号**。两者同名不同义，`Z4` 若再用它，还得再声明一次。
3. **同层多颗共轨是妥协**：真实里同轨两颗会共振散掉。链状数据（每域 10 项 9 边）每层恰好一颗、不触发；有分支的域会触发。守住规格明写的「共面」「同向」两条，代价是这一条。
4. **开普勒 `T ∝ a^1.5` 未实现**：本笔只有静态相位，没有运动就没有周期可验。`C-56` 仍登记在常量表里，归运动那一笔 —— 这一条**属未实现，不属未验**，不在 `STR` 的未验项里冒充「待观察」。
