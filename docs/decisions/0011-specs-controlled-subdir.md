# ADR-0011 · `specs/` 下再分一层：受控交付物迁入 `controlled/`

- **状态**：已接受（2026-10-23 执行完毕，同日落地）
- **日期**：2026-10-23
- **决策人**：liberal
- **覆盖范围**：`docs/specs/` 的内部层级 —— 五份受控交付物（`SCMP` `SRS` `SDD` `STP` `STD`）的落点；`app/tool/docs/rules.dart` 的四个路径常量；`app/tool/docs/migrate_docs.dart` 的批 8；技能包 `nebula-project-builder` 的落点定义与六项检查。**不影响**五份的内容、文件名与版号规则，也不影响其余 21 份活文档的位置

## 背景

### 一、`specs/` 里装的是五类东西，而 `ADR-0008` 只给了一条判据

`ADR-0008` 给 `specs/` 的定义是「**应当如何**」—— 可执行、可验收的规范。按这条判据，下面五类都合格，于是全平铺在同一层（2026-10-23 实测 **26 份 / 7,870 行 / 零子目录**）：

| 类 | 份数 | 说明 |
|---|---|---|
| 十卷主题规格 | 10 | `FND`…`SYNC`，被 5–14 个文件引用 |
| 八份横切表 / 规格 | 8 | 含 3 份整体或分层作废（`VIEW` `channel-table` `constants`） |
| 两份工程规范 | 2 | `git-conventions` `dependency-licenses`，**读者是贡献者不是实现者** |
| **五份受控交付物** | 5 | `scmp` `srs` `sdd` `stp` `std` —— **有版号序列、受 `D2` 管** |
| 索引 | 1 | `00-index` |

`ADR-0008:86` 自己写下过这条判据的失效条件：**「一个目录的定义要靠枚举才说得清，说明它不是一类」**。现在 `specs/` 正落在这个状态 —— `docs/README.md` 描述它用的是「10 份主题规格 + 8 份横切表/规格 + 2 份工程规范」，**枚举了 20 份，实际 26 份**。

### 二、三处现时陈述已经与实物对不上（本次硬发现）

| 位置 | 原文 | 与实际 |
|---|---|---|
| `docs/README.md:18` | 「**本仓不含交付物**：六段 25 种已按 `ADR-0009` 移出本仓托管」 | `ADR-0009:169` 写着「仓内受控 **9**（现有 5 + 待建 4），全部落 `docs/specs/`」—— 出仓的是 11 份，不是全部 |
| `docs/README.md:10` | `specs/` = 「10 份主题规格 + 8 份横切 + 2 份工程规范」 | 20 份，实际 26；漏的正是受控五份与索引 |
| `specs/00-index.md` | 名为「设计规格 · 索引」 | 实测只索引 **16/26**：`path-rules` `minimal-pack` `skeleton-catalog` `git-conventions` `dependency-licenses` 与受控五份在该文件里各 **0 次** |

第三处比前两处严重：`00-index` 是 `specs/` 的唯一入口，**索引漏一半成员等于入口失效**。

### 三、引用密度是两极分化的，分界线正好落在「受控 / 活文档」

| 层 | 被引用（文件数 / 次数） |
|---|---|
| 横切层 | `entity-fields` **20 / 51** · `constants` **20 / 46** · `event-types` **16 / 41** |
| 受控层 | `srs` **1 / 2** · `sdd` **1 / 2** · `stp` **2 / 4** · `std` **3 / 7** · `scmp` **4 / 31** |

受控五份引用少**不是缺陷** —— 它们的读者是审计与交接，不是开发者。但这恰好说明它们与主题卷不在同一层：**同一层的文件，读者与更新节奏应当相近**。

### 四、受控只会变多

`ADR-0009:169` 已登记待建 4 份受控（`IRS` `DRD` `IDD` `DBDD`）⇒ 受控将由 **5 变 9**。越晚切，要改的路径越多。

## 决策

### 1. 只切一刀，切在纪律边界上

| 目录 | 装什么 | 判据 |
|---|---|---|
| `docs/specs/`（根） | 21 份活文档：10 卷 + 8 横切 + 2 工程规范 + `00-index` | 不设版号，更新以 `git log` 为准 |
| `docs/specs/controlled/` | 5 份受控交付物：`scmp` `srs` `sdd` `stp` `std` | **有版号序列、在 `D2` 管辖内** |

**判据是「有没有版号序列」，不是文档主题。** 这一句话就够，不需要枚举 —— 这正是 `ADR-0008:86` 要求的形态。

### 2. 目录说明改成可验证的结构陈述，不留枚举

`docs/README.md:18` 的「本仓不含交付物」被替换成：

> **受控交付物在 `specs/controlled/`**：五份有版号序列、受 `D2`–`D6` 管，是五个目录**唯一的版号例外**。另有 11 份按 `ADR-0009` 出仓托管，那批的版号与冻结不归本仓管 —— **「出仓」与「受控」是两件事**：前者换仓库，后者换纪律。

这句话可验证：`ls docs/specs/controlled/` 出五份，`grep -c "版号" docs/specs/controlled/*.md` 出五份有历史节，两处对得上就是真的。

### 3. `00-index` 补成全覆盖，并把「新增即回填」写成判据

新增三节：三.1 规则表与规格（`path-rules` `minimal-pack` `skeleton-catalog`）· 三.2 工程规范（2 份）· 三.3 受控交付物（5 份）。补齐后 26/26。

判据：**`specs/` 下任何新增文件，若在 `00-index` 里 grep 到 0 次，就是漏登记。**

## 被否方案

| 方案 | 改动面（实测） | 否掉的理由 |
|---|---|---|
| **A 不拆，只修三处口径** | 3 处文字，零链接、零代码 | 治不了根 —— 五份受控继续与活文档混在根下，「本仓不含交付物」这句永远说不圆，只能靠加限定语绕 |
| **C 按内容拆三类**（`volumes/` `tables/` `engineering/`） | **270+ 处**：158 条内部互引全改 + 93 条跨目录 + `00-index` 全表 + `rules.dart` 4 常量 + `itemIdToFile` + `docs/README` 三节 + `AGENTS.md` 三处 | `specs/` 从「一类」变**容器**，`ADR-0008` 的「一个目录一个词」判据当场作废；且判断「一份文档属主题卷还是横切表」仍需枚举，等于把同一个病挪到下一层 |
| **D 改名加前缀**（`ctl-scmp.md`） | 与 B 相近 | 比搬目录更伤 `git log --follow`：改名是 `R`+内容变更，搬目录是纯 `R`；且前缀把「受控」写进文件名，将来层级再变又要改一次名 |
| **E 回迁 `docs/deliverables/`** | 要改 `.swe-init.json` 的 `docsProfile.dirs`（有版本号的既成事实） | `ADR-0009` 刚否决过；且 `deliverables/` 的语义是「25 种国标文档的家」，不是「有版号的那批」 |

## 影响

### 1. 链接与路径（实测，不是估算）

| 项 | 数量 | 处理 |
|---|---|---|
| 链接目标需重算 | **67 条** | `migrate_docs.dart --batch 8` 自动算（`MANUAL` 0 条） |
| 行内代码 / 链接文本里的旧路径 | **18 处** | 手改 —— 迁移器**只改链接目标**，不改链接文本、不改行内代码 |
| `rules.dart` 路径常量 | **4 个** | `docFiles` 3 + `sddFile` 1 |
| `migrate_docs.dart` | 批 8（5 条映射） | 新增 |

⚠️ **链接文本没改 = 功能正常但看着是假话**：显示文字仍写旧路径、目标已指新路径的链接，点得动、但读起来是错的。`D6` 查不出来（它只验目标存不存在），只能人工扫 —— 本笔实测这类共 **8 处**，全在 `docs/baselines.md`。

### 2. 跨仓影响：技能包硬编码了旧路径

技能 `nebula-project-builder` 是**用户级模板**，对每个新项目都生效：

| 位置 | 原文 | 不改的后果 |
|---|---|---|
| `SKILL.md:181` | 「只读检查六项：`docs/specs/scmp.md` · `.git/` · …」 | 本项目在技能眼里变成「第 1 步未完成」，下次问「下一步」得到错误答案 |
| `references/docs-skeleton.md` | 「配置管理计划 → `specs/scmp.md`」（落点**唯一定义**） | 新项目仍按旧路径落，两边分叉 |

⇒ **同批改技能，把 `controlled/` 定成标准形态**（不写兼容分支：两处定义落点等于 SSOT 破了）。

### 3. 判据层面：无变化

- `D2` 覆盖面仍是四份 + 仓外 `SDP`；`D3` / `D4` / `D5` / `D6` 仍只认四份 —— **改的只是路径常量，判据逻辑一行未动**。
- 用例表仍 791 条、`flutter test` 仍 416 passed、不升版号（纯结构搬迁，内容未变）。

### 4. 历史保留

五份全部 `git mv`，`git status` 应为 `R` / `RM`（改写链接后内容有变）。判据：`git log --follow --oneline docs/specs/controlled/scmp.md` 能追到 `deliverables/` 时代；出现 `D`+`A` 说明历史断了。
