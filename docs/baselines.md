## 登记纪律

### 一、锚点提交的含义

**锚点提交 = 冻结那一刻的 `main` HEAD**，一行一个，记的是「这条基线在哪一刻被切下来」。

⚠️ **锚点 ≠ 组成笔**。`specs/scmp.md` §3.1 / §3.2 / §3.4 的「合并提交」列记的是**构成该基线的每一笔**（`BL-1` 是三笔 `34dc617` / `b828172` / `74b6708`），粒度不同。把组成笔抄进本表，就是把「一句话能说清的位置」扩写成「一串需要自行排序的证据」—— 那是复制，不是登记。

### 二、四条基线的锚点为何全部是「未登记」

`BL-0`–`BL-3` 的登记时点，`SCMP` 原表只有「内容 / 登记日期 / 状态」三列，**从未记录当时的 HEAD**。这是**登记缺陷，已如实标注，不补推**：

- 可考证的只有各笔的合并提交（`296ad52` 初始化 · `266ff54` #16 · `639784f` #21 …）；
- 但「最后一笔合并之后、下一笔之前」的 HEAD **没有任何记录能证明**，用最后一个合并提交反推，是把推测写成事实。

**判据**：宁可留一个显式的空洞，也不要填一个看起来完整的推测值 —— 前者会被追问，后者不会。

### 三、今后新登记的基线

| 要求 | 判据 |
|---|---|
| 锚点必填 | 冻结当刻的 `main` HEAD（sha 或 tag）；**无版本控制时才**改用「日期 + 版本 / 交付包名」并写声明 |
| 只 append | 已登记的行不改。勘误也用追加：新行写明「勘误 `BL-n` 的哪个字段，原值 …」 |
| 标识单调递增 | `BL-n` 不复用，废弃不删号 |
| 缺口写在登记处 | 带缺口仍可登记，但缺口必须写在本表「已知缺口」列 + `specs/scmp.md` 对应 §3.x 里，**不留口头** |
