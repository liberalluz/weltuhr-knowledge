## 一、目的与范围

界定本项目的**配置项**（哪些产物受版本控制与变更控制）、**基线**（哪些组合被冻结为可回溯的节点）与**变更入口**（改动走哪条路径）。

**不管**：具体提交格式与分支命名 → [`../../guides/git-conventions.md`](../../guides/git-conventions.md)；产品排期 → [`SDP-软件开发计划.md`](SDP-软件开发计划.md)。

## 二、配置项识别

| 类别 | 路径 | 版号形态 | 变更入口 |
|---|---|---|---|
| 客户端代码 | `app/` | 无独立版号，随产品版本 | PR → `main` |
| 服务端代码 | `server/` | 无独立版号，随产品版本 | PR → `main` |
| 内容源数据 | `content/` | **内容包 tag** `pack/<space>/vX.Y.Z` | PR → `main`，发布打 tag |
| 基础设施 | `infra/` | 无独立版号 | PR → `main` |
| 交付物文档 | `docs/deliverables/` | **`vX.Y.Z` 独立递增** | PR → `main`，正文注明版号变化 |
| 活文档 | `docs/design/` `reference/` `guides/` `adr/` | **不设版号**（以 `git log` 为准） | PR → `main` |
| 仓库级约定 | `.github/` `.gitattributes` `.gitignore` | 无独立版号 | PR → `main` |

**三条识别判据**：

1. **生成物不入库**：`content/*/dist/` 由 `content/tools/build.py` 本地构建，`.gitignore` 覆盖，CI 有判据（见 `../../.github/workflows/content-checks.yml`）。
2. **内容包版本与代码版本解耦**：内容包打 tag，不打产品 tag；递增**按「是否让既有进度失效」判**（删项 / 改 `Item.id` / 改 `⪯` = major），不按提交类型判。
3. **活文档不设版号**：手写「最后更新」头会变成第二份会过期的记录。

**已知缺口（登记于 §三 而不隐去）**：

| 缺口 | 实际状态 | 处置 |
|---|---|---|
| `B1` 出口判据「**三端**空壳可启动」 | 只有 **Windows** 人工验证过。`macOS` / `iOS` **未执行** —— 不是通过，不是失败 | 挂到 `B8`（制品与分发）：该批本就要出三端安装包，启动验证是打包必经步骤 |

**为什么带缺口仍可登记**：基线的作用是给未来一个**可回溯的节点**，不是「一切都已验收」。把缺口写清再冻结，比等所有验收做完才登记更可回溯 —— 后者会让「这版代码到底验过什么」失去记录。前提是缺口**写在登记处**，而不是留在口头。

### 3.3 基线之间的增补判据

| 情形 | 处置 |
|---|---|
| 新增基线未覆盖的配置项 | 新开基线编号，**不修改旧基线** |
| 旧基线的配置项内容变更 | 走变更控制（§四），记入新基线 |
| 旧基线的记录本身有误（勘误） | 可原地修正，但须在修订历史写明「勘误」及原文 |

**为什么不允许回溯改旧基线**：基线的作用是「给未来一个可回溯的节点」。允许回溯修改，基线就退化成「当前状态的快照」，而当前状态本来就有 `main` 可查。

## 四、变更控制

| 变更类型 | 路径 | 附加要求 |
|---|---|---|
| 常规 | 特性分支 → PR → squash → `main` | PR 正文含自验证证据 |
| 契约 / 事件 schema / 内容包格式 | 同上，**须他人评审**（无人数豁免） | 同步更新 `IRS` 与 `IDD`，不得只改一侧 |
| 架构级 | 同上 | 新增或修订 ADR；勘误与实质修订须分别留痕 |
| 基线内配置项 | 同上 | 变更须可回溯到基线编号 |

变更分级（A/B/C/D）的判据见 [`../../guides/git-conventions.md`](../../guides/git-conventions.md) §4.4。

### 5.2 状态一览的维护责任

本表**不是自动生成的**，每次交付物版号变化须手工更新。这是刻意选的：

| 方案 | 问题 |
|---|---|
| 手工维护本表（现状） | 会滞后，但滞后是可发现的（与各文件头部对不上） |
| 脚本扫各文件头部自动生成 | 各文件头格式必须高度一致，且版号一改就要重跑；CI 会因此需要写权限 |

**判据**：本表滞后属**已知代价**，不是缺陷。若将来 25 份全部写实、版号变动频繁，再改成脚本生成，届时本表降为「生成物的说明」而非权威处。
