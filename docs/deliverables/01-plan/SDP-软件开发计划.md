## 四、进度与里程碑

### 4.1 总计划（阶段级）

| 阶段 | 里程碑 | 关键内容 | 目标版本 | 出口判据 |
|---|---|---|---|---|
| **P1** | 学习主链贯通 | 三端骨架 · 事件内核 · α 内容包 · 三视图 · Planner · 修习 Runner · 量化与保持 · 制品与分发 | `v0.1.0` | 五动作闭环跑通；三端安装包可安装、可启动、**能加载到内容** |
| **P2** | 笔记与治理 | Note 三层 · 单向导出 · overlay 双平面 | `v0.2.0` | 笔记可写可导出；治理层不侵入事件内核 |
| **P3** | 上架与分发 | 商店审核 · 更新机制 · 分发渠道 | `v1.0.0` | 通过 App Store 审核；分发渠道可用 |
| **P4** | 服务端与跨设备 | 服务端部署 · 跨设备 HLC 合并 · 私有化交付包 | `v1.1.0` | 双端同步一致；私有化试点交付 |

**三条硬约束**：

1. **阶段代号 ≠ 版本号**。阶段用 `P` + 序号（`P1`–`P4`），版本用三段 `vX.Y.Z`。两者不得混写（如「`V0.1` 阶段」既非阶段代号也非合法版号）。
2. **阶段名只说交付了什么**，不写程度词。范围最小、可用、可行这类信息归出口判据列 —— 写进名字会让名字随判据变。
3. **目标版本单调递增**：`0.1.0` → `0.2.0` → `1.0.0` → `1.1.0`，连续无倒挂。

### 4.2 分阶段计划 · P1（学习主链贯通 → `v0.1.0`）

| 批次 | 里程碑 | 关键内容 | 出口判据 | 出处 |
|---|---|---|---|---|
| **B1** | 三端骨架 | `app/` 三端脚手架 · `core/{constants,enums,errors,json}` · 实体 `content` / `plan` / `state` | 三端空壳可启动；`core/` 无 Flutter import | 明文 |
| **B2** | 事件内核 + α 包 + 投影帧预算 | 事件表 · HLC · `fold(events, asOf)` · 定位引擎 · `⪯` DAG 校验 · α 最小真实包 · 帧预算实测 | `fold` 单测绿；定位对 α 包正确；帧预算达标 | 明文 |
| **B3** | 三视图 | `Z0–Z4` · 六通道两叠加 · 三视图投影 · HUD 七区块 · 树四类行 · 详情 · 快速定位 | α 包上三视图可渲染、快速定位可用 | 推定 |
| **B4** | Planner | 三段流程 + 实时预览 + 三段自建 | 建 Plan 三段流程跑通 | 推定 |
| **B5** | 修习 Runner | 七步行为 · 三入队源 · 步骤游标 · 六类算子 · 检验两出口 | 判合格写事件（五动作闭环最后一环） | 推定 |
| **B6** | 量化与保持 | 掌握度两维 · 进度离散 · 三层单调 · FSRS 落位 | 掌握度与进度指示随事件正确变化 | 推定 |
| **B8** | 制品与分发 | 三端制品 · `PackLoader` 改为 exe 同级解析 · 签名公证 · 内测分发 | 三端安装包可安装、可启动、**能加载到内容** | 推定 |

- **闸门**：每批以一道出口闸门收尾（`G1`–`G9`），过不了不进下一批。**闸门的具体断言随该批开工写入对应 PR 描述，本文件只登记闸门与批次的归属，不复制断言内容** —— 复制一份就有两份可改。
- **批次编号不重排**：`B7` 属 `P2` 却在 `B8` 之前编号。重排会让所有已讨论过的批次号失效；表格按阶段分组，阅读顺序不受影响。
- **出处等级**：「明文」= `adr/0002` 有直接表述；「推定」= 按其批次框架推出，ADR 无逐条对应。推定项在**首次开工时回填为明文**，回填须给出新增依据。

### 4.3 分阶段计划 · P2 / P3 / P4

| 阶段 | 批次 | 里程碑 | 关键内容 | 出口判据 | 出处 |
|---|---|---|---|---|---|
| **P2** | `B7` | 笔记与治理 | Note 三层 · 单向导出 · overlay 双平面 | 笔记可写可导出；治理层不进内核 | 明文 |
| **P3** | 未拆批 | 上架与分发 | 商店审核材料 · 更新机制 · 分发渠道 | 过审 + 渠道可用 | 本次新增 |
| **P4** | `B9` | 服务端落位 | 服务端部署形态 · 云 / 私有化 · 跨设备 HLC 合并 | 双端同步一致 | 明文 |

**两处分界判据**：

1. **按「是否纯客户端」切**，不按体量对半。`P2` 全部可离线验收，`P3`/`P4` 的验收才只需关注商店与服务端本身。
2. **跨设备 HLC 合并随服务端**，不提前到 `P2`。合并算法没有第二台设备就写不出可观测断言（`X-05`），提前做只能得到构造出来的证据，风险被暂时掩盖。
3. `P3` 不预先拆批 —— 拆批依赖 `P4` 结束时的真实形态，现在拆只能凭空猜。
4. **私有化交付包在 `P4` 而非 `P3`** —— 它依赖服务端容器，订单不能排在依赖之前。

### 4.4 关键路径

```
α 真实内容包 → 投影帧预算 → 事件内核 → 三视图 → Planner → 修习 Runner → 制品与分发
```

- `P2` / `P3` / `P4` **都不在 `v0.1.0` 的关键路径上**。
- 上架不等服务端：`adr/0002` 明文「服务端不在关键路径」，若上架须等服务端，服务端即成关键路径，与该裁定矛盾。
- `P1` 内 `B8` 排最后但**不是「最后再说」**：所有路径假设都建立在「从仓库根跑」之上，只有打包才会让它们暴露。`project-language` 实际上过这个当（上架包里没有任何语言包）。
