## 一、范围

`v0.1.0` 的范围 = **一条学习主链在本地端到端贯通**，五个动作构成闭环：

```
加载空间 → 圈定目标 → 建 Plan → 学一项 → 判合格写事件
```

范围裁定与理由见 [`../../adr/0002-dev-order-vertical-slice.md`](../../adr/0002-dev-order-vertical-slice.md) 与 [`../../adr/0005-three-axis-tree-replaces-six-axis.md`](../../adr/0005-three-axis-tree-replaces-six-axis.md)（本文件不复制）。`v0.1.0` 之外的条目由 §4.3 承接。

**明确的边界**：`P1` **纯本地** —— 无账号、无服务端、无同步。这是 [`ADR-0005`](../../adr/0005-three-axis-tree-replaces-six-axis.md) 决策 6 对 `ADR-0004`「账号是使用前提」的**收窄**：本地浏览 / 学习 / 复习 / 自建内容都不需要账号，只有跨设备同步、市场安装、机构作用域需要。笔记、治理、覆盖层、**跨设备同步**均不在 `v0.1.0` 内。

**三条硬约束**：

1. **阶段代号 ≠ 版本号**。阶段用 `P` + 序号（`P1`–`P4`），版本用三段 `vX.Y.Z`。两者不得混写（如「`V0.1` 阶段」既非阶段代号也非合法版号）。
2. **阶段名只说交付了什么**，不写程度词。范围最小、可用、可行这类信息归出口判据列 —— 写进名字会让名字随判据变。
3. **目标版本单调递增**：`0.1.0` → `0.2.0` → `1.0.0` → `1.1.0`，连续无倒挂。

**两处分界判据**：

1. **按「是否依赖服务端或第二台设备」切**，不按体量对半。`P2` 四批里 `B7` / `B16` 可纯本地验收，`B10` / `B11` 才引入服务端；`P3` / `P4` 的验收只需关注商店与服务端本身。**原判据「`P2` 全部可离线验收」随 `B10` 移入而失效** —— 它在当时成立，是因为账号还压在 `P1`。
2. **「搬运」进 `P2`，「合并」留 `P4`**。`ADR-0004` 把增量同步提前到 `P2`（`B11`），但它只搬不判（`X-09`）；**双向合并算法**仍留 `P4` —— 没有第二台设备就写不出可观测断言（`X-05`），提前做只能得到构造出来的证据，风险被暂时掩盖。
3. `P3` 不预先拆批 —— 拆批依赖 `P4` 结束时的真实形态，现在拆只能凭空猜。
4. **私有化交付包在 `P4` 而非 `P3`** —— 它依赖服务端容器，订单不能排在依赖之前。

### 4.4 关键路径

```
实体层地基 → 骨架数据 → 插件化四类包 → 容器树七级 → Planner → 地形层 → 修习 Runner → 量化与保持 → 3D 宇宙 → 制品与分发
```

- **`B2`（事件内核）不在箭头链上，但前置一切**：已完成，只增 `navigate`；`userId` 那部分已随 `B4` 第 1 笔落地（`C-93`），不再单独安排。
- **`B13a` / `B13b` 必须排在 `B4` 之前**：`B4` 的候选集依赖树的父子结构，在旧 `Item` / `Edge` 上重构不划算 —— 那等于给一份注定作废的实体打补丁。**`B13a` 是 `P1` 里唯一不依赖外部资料的起手点**（输入只有台账与 `ADR-0007`），`B13b` 则要等三份目录到位。
- **`B17a` 排在 `B4` 之前是硬依赖**：`B4` 三段流程第一步就是「圈定目标」，而圈定动作发生在树与宇宙里。先有可下钻的七级树，`B4` 的验收才不是构造输入。
- **`B17` 拆两半的理由**：`ADR-0006`（3D 技术栈与视觉风格）当时**未定**，现已决。拆开后它只阻塞 `B17b` 与 `B8`，**不阻塞 `B4`–`B6`**；不拆则一个未决 ADR 堵死整条主链 —— 那等于把「视觉方案没定」放大成「什么都做不了」。**拆批的价值不因 ADR-0006 落地而消失**：这次之所以没被堵，是因为 ADR 恰好定得早，而不是因为拆批多余。
- **`B17b` 可与 `B15`–`B6` 并行**：它的输入只有树结构与骨架包，与地形层、修习 Runner 无交集，闸门独立。
- `P2` / `P3` / `P4` **都不在 `v0.1.0` 的关键路径上**。
- **上架不等同步**：`P3` 上架不需要 `B11` 完成 —— `v0.1.0` 交付时连账号都还没有，同步是下一个版本的能力。
- `P1` 内 `B8` 排最后但**不是「最后再说」**：所有路径假设都建立在「从仓库根跑」之上，只有打包才会让它们暴露。`project-language` 实际踩过这个当（上架包里没有任何语言包）。**本版后更紧**：`B14` 起有四类包 + 骨架包内置，`PackLoader` 若仍按单一目录探测，装出来的包会「能启动但一棵树都没有」。

### 7.2 从台账里能读出的五件事

1. **四条已发生的文档类风险（R-01 / R-10 / R-11 / R-12）都不是「忘了写」，而是「规则写得看似成立、实际失效」**。R-01 是四处规则同时缺位，R-10 是给降标做了合法性包装，R-11 是判据与产出冲突。这类问题的共同特征是：**文档自洽，行为不自洽**。
2. **两条已发生的 CI 类风险（R-02 / R-03）都是「判据静默通过」而非「判据报错」**。静默通过比误报危险得多 —— 误报会有人去查，通过不会有任何人发现。
3. **`R-04` / `R-13` 仍属「现在不办、后面无解」**，是 §4.5 长周期前置的来源（`R-20` 同族，本版新增）。新增的 `R-15`–`R-18` 属**同族** —— 它们的共同特征不是「难」，而是**违反了不会有任何东西变红**（`R-08` 的判据）：服务端没登录拦不住也不会报错、包版本不一致时丢一条事件没人知道、两个账号的进度混在一起只表现为一个「莫名其妙」的数字。**这类风险只能靠显式裁定堵，不能靠测试发现**，所以它们被写成了 `ACC` / `SYNC` 里的裁定，而不是留待实现时注意。其中 `R-15` / `R-16` 已由决策 6 关闭 —— 关闭方式也是裁定，不是修好了。
4. **`R-06` 是台账里唯一一条「结案但结论不等于『没问题』」的**：帧预算达标，风险落点却从 CPU 移到光栅 × 覆盖面积。原判据（CPU `8 ms`）盯错了地方 —— 实测 CPU 只花 `0.03 ms`；而小窗读数（余量 57%）与基准窗口读数（占预算 88%）指向相反的行动。**性能类读数必须带测量前提**，否则「通过」只是一个尺寸下的巧合。
5. **`R-19` 是台账里第一条「方法论对、地基换了」的风险**。它与 `R-01` / `R-10` 同族 —— 文档自洽、行为不自洽。**区别在它连文档都还没来得及不自洽**：`B3` 完工时所有断言是绿的，作废不是因为写错，是因为**对的东西建在错的地上**。这类风险唯一的判据是「这个前提会不会被换掉」，而前提写在需求里，不在测试里。**反证是现成的**：本次作废的 `B12` 九笔里，每一笔都有独立反证、每一道断言当时都咬得住 —— 它们确实证明了自己声称的事，只是那件事不再需要被证明。**教训不是「前后要一致」，是「视觉层不该先于本体定下来」**：`B3` 排在 `B13` 之前，是因为当时还没有 `B13`。

## 八、计划变更控制

**填充时点已在 `v0.11.0` 兑现**：本节原注释写「首次发生计划变更时填」，`ADR-0005` 换地基导致 `P1` 重组即首次（`PC-01`）。

### 8.1 变更分级

| 级别 | 触发条件 | 审批 | 记录 |
|---|---|---|---|
| **一级 · 里程碑变更** | 阶段增减 · 目标版本改号 · 出口判据增删 | 维护者决策 | 记入 `DPMR` 并说明原因 |

变更分级（A/B/C/D）的**操作**判据见 [`../../guides/git-conventions.md`](../../guides/git-conventions.md) §4.4；本节只管「排期这一层的变更算什么级别」。

### 8.2 三条判据

1. **架构级变更先立 ADR，再改本表**。本表只承载「何时做」，不承载「为什么这么做」。`ADR-0005`（为什么）→ 本版（何时）即此路径。反向操作 —— 先改排期再补 ADR —— 会让排期变成架构决策的事实源。
2. **已完成批次的判据，不作废就不改**。判据一旦在闸门上用过，改写等于让已完成的工作失去证据。作废须**保留原行 + 标状态**（见 §4.2 作废登记），不得删除 —— 删掉之后没人能分辨「这一批是没做，还是做废了」。
3. **笔序不进本表**。笔序随首笔写入 PR 描述，同一事实不在两处维护（与 `R-10` 同一条判据）。
