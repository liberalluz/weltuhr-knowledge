# 依赖许可核查

> 活文档，不设版号。**用途**：`LICENSE` 只声明本项目，**依赖的许可义务不因本项目选了宽松协议而消失**。本文件是那条义务的落点。

## 一、本项目协议

**Apache-2.0**（见仓根 `LICENSE` 与 `NOTICE`）。
含义：允许闭源集成与私有化交付；须保留版权与许可声明；修改文件须显著标注；含 `NOTICE` 时须随分发保留。

## 二、核查流程（每次引入依赖时）

```bash
# 客户端
cd app && flutter pub deps --style=compact

# 服务端
cd server && dart pub deps --style=compact
```

逐项记录到 §三 的表格，判定：

| 依赖许可类型 | 本项目可否使用 | 处置 |
|---|---|---|
| 宽松（MIT / BSD / Apache-2.0） | ✅ | 记入 `NOTICE` 的致谢区 |
| 弱传染（LGPL / MPL） | ⚠️ 条件可用 | 不得静态链接或修改其源码；单独标注 |
| 强传染（GPL / AGPL） | ❌ **禁止引入** | 与 Apache-2.0 分发定位冲突 |
| 无许可声明 | ❌ **禁止引入** | 无许可 = 保留全部权利，不可用 |

## 五、纪律

- **不得自证**：许可结论以**官方许可文本**与**依赖的实际声明**为准，不以「应该是 MIT 吧」下结论。
- 传染型依赖的合规结论必须**单独成行写明**，不能只标一个 ⚠️。
- 依赖升级可能改变许可（少见但存在），升级 PR 须复核本表。
