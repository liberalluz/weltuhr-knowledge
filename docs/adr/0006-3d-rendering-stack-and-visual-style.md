# ADR-0006 · 3D 渲染栈与视觉风格

- **状态**：已接受
- **日期**：2026-10-20
- **决策人**：liberal
- **覆盖范围**：[`ADR-0005`](0005-three-axis-tree-replaces-six-axis.md)「未在本 ADR 决定」的第一项（3D 渲染技术栈）· [`ADR-0003`](0003-view-radial-axis-and-channel-thresholds.md) 的通道判据（**前提已由 `ADR-0005` 取代，本 ADR 只接其视觉资产部分**）· `SPEC-VIEW-*` 的渲染前提

## 背景

视觉侧的四条已定，本 ADR 不重开：

| 项 | 结论 | 出处 |
|---|---|---|
| 背景 | 烘焙天球 —— Yale BSC5 公有领域 9,110 颗 + 程序化补到 2 万 | 需求侧 |
| 前景 | A 案外观（自绘）+ B 案标注层（Flutter Widget 叠加） | 需求侧 |
| 色彩 | **色温让给轴** —— 学科青 / 专业琥珀 / 角色洋红紫 | 需求侧 |
| 布局 | 同心球壳，半径按对数等比 | 需求侧 |

缺的是**怎么在 Flutter 上把它画出来**。四条硬约束：

1. **2 万颗星不能用 `drawPoints`** —— 性能闸门已禁 >10,000 点，且 `drawRawPoints` 在 2 万量级不可行（旧结论）。背景必须是一张**烘焙贴图**，运行时零顶点。
2. **`bloom` 是「接近真实宇宙」的硬需求** —— 星点光晕是这项观感最直观的一项。而 bloom 需要**多 pass**（亮部提取 → 多级模糊 → 合成）。
3. **三端**：Windows / macOS / iOS，一套代码。
4. **`core/` 不得 import Flutter** —— 渲染实现只能落在 `features/universe/`。

第 2 条是选型的实际决定项：**Flutter 的 `FragmentProgram` 是单 pass 的**，拿不到离屏目标做二次处理，因此纯 shader 方案先天做不出 bloom。

## 决策

### 1. 渲染栈 = `flutter_scene`

| 项 | 取值 |
|---|---|
| 包 | `flutter_scene` |
| 版本 | `^0.23.0` |
| 生效范围 | `app/features/universe/presentation/` —— `core/` 与 `application/` 不得 import |
| 平台 | Android / iOS / Linux / macOS / Web / Windows 全覆盖；本项目只用三端 |

`^0.23.0` 在 pub 语义下等价 `>=0.23.0 <0.24.0`，即**只接受 0.23.x 补丁**。0.24 须手动升并重跑 spike —— 该包 0.14 与 0.22 均有 `BREAKING`，不能跟 `latest`。

选它的唯一实质理由：**`Scene.skybox` + `EnvironmentSkySource` 与 `Scene.postProcess` 同时提供**，前者吃 equirect 全景图，后者含 bloom / 色彩分级 / 暗角 / 景深。自研要分别实现这两块，其中 bloom 的自研成本不低于整个天球采样。

### 2. 使用面限定：只用 skybox 与后处理

`flutter_scene` 是完整 3D 引擎（PBR、物理、骨骼动画、粒子、glTF、GI）。**本项目只用其中三项**：

- `Scene.skybox` + `EnvironmentSkySource` —— 承载烘焙天球
- 相机（球心视角，只旋转不平移）
- `Scene.postProcess` —— bloom（必需）· 色彩分级（`色温让给轴` 的全局压调）· 暗角（可选）

**明确不用**：物理后端 · 骨骼动画 · 粒子系统 · glTF 资产 · 全局光照 · 阴影。理由：这些每一样都会把依赖面与升级风险放大，而对「从球心看星空」零收益。行星与恒星都**不是 3D 模型**，是贴图上的点 + Flutter Widget 标注。

### 3. spike 闸门：`B17b` 开工前必须先跑

Impeller 在三端的启用状态、`flutter_scene` 的实际帧时间，**只能实跑确认**。沙箱不能 `build`/`run`，故本 ADR 不预置「已验证」结论。

**spike 内容**（三端各一次）：最小场景 = 天球贴图 + 1,200 个 billboard 点 + bloom 开启。

| 判据 | 阈值 |
|---|---|
| 帧率 | P50 ≥ 30 fps，P95 帧时间 ≤ 50 ms（`B17b` 的 60 fps 目标不在 spike 判据内 —— spike 验「能不能跑」，不验「跑得多好」） |
| 白屏 / 崩溃 | 0 次 |
| 渲染路径 | 无 `PlatformView`、无 fork、无原生平台代码 |
| 三端一致 | 三端均须通过；任一端不过即判 spike 失败 |

**失败处置**：回落 `FragmentProgram`（每像素反投影）+ 预渲染光晕 sprite，并把本 ADR 标为**已取代**、新立 ADR 记录取舍。回落后接受「无真 bloom」这一观感损失，须在 ADR 中显式写明。

### 4. 天球贴图是构建产物，不入库

一张 4096×2048 的 equirect 全景图约 8–15 MB（PNG）/ 2–4 MB（KTX2），而 `ADR-0005` 决策 2 给骨架包的预算是「数百 KB」—— **贴图不能进骨架包**。

| 项 | 结论 |
|---|---|
| 生成 | 构建期由 Yale BSC5 星表 + 程序化补充烘焙，脚本置于 `infra/` |
| 入库 | **否** —— 仓规「构建产物不入库」直接适用（同 `content/` 的 `dist/`） |
| 分发 | 随制品打包，不进骨架包，不参与包版本握手 |
| 分级 | 4096×2048（默认）/ 8192×4096（FOV 收窄时）/ 16384×8192（极限，仅桌面） |
| 格式 | KTX2（Basis 压缩）优先 —— `flutter_scene` 原生支持，且体积是 PNG 的 1/3 |

这条同时解决一个口径冲突：`ADR-0005` 的「骨架包数百 KB」与「2 万颗星」并不矛盾 —— **星星在贴图里，不在包里**。

### 5. 视觉实现口径

| 维度 | 实现 | 判据 |
|---|---|---|
| 天球 | 贴图按 FOV 选级，随相机姿态采样 | 无接缝、无极区畸变 |
| 星点光晕 | `postProcess` 的 bloom，阈值与强度入常量 | 亮星有光晕、暗星不糊 |
| 轴色 | 前景点按 `axis` 着色（青 / 琥珀 / 洋红紫） | 三个轴的恒星在同一屏内可辨 |
| 亮度 | 按掌握度映射，单调不减 | 已学项比未学项亮 |
| 标注 | Flutter Widget 叠加，≤60 条，`Paragraph` LRU 200 | 超 60 走聚合，不缩字号 |
| LOD | 同屏语义节点 >1,200 转聚合 | 帧率不因节点数抖动 |
| 过渡 | 虫洞过渡为相机弧线插值，时长入常量 | 中途不出现空白帧 |

## 被否方案

**① `FragmentProgram` 每像素反投影采样。**
天球采样质量最高（无顶点、无接缝、无极区畸变），投影数学还可用 CPU 参考实现单测。**否因是单 pass**：拿不到离屏目标，bloom 只能做单次径向近似的假泛光，拖影明显。若 spike 失败，本方案转为回落目标。

**② `flutter_gpu` 自写渲染器。**
效果上限与 `flutter_scene` 持平，且完全按需裁剪。但 bloom、LOD、tone mapping、纹理 mip 全要自建，工作量等于重造前者；而 `flutter_gpu` 本身 API 仍在演进。**为省一个 0.x 依赖而自建一套引擎，是把依赖风险换成工期风险**。

**③ `drawVertices` 球面网格 + `Canvas` 纹理映射。**
纯 Canvas、零依赖、投影可完整单测，对测试最友好。但球面网格在极点必然挤压变形，接缝处采样会出现细线；且同样无多 pass。天球全景里这两项都是硬伤，观感离目标最远。

**④ 平台原生（macOS Metal / Windows D3D12 / iOS Metal）经 FFI 或 `PlatformView`。**
性能最好，但三端三套实现，且 `PlatformView` 会失去与 Flutter 的合成能力 —— 标注层要浮在 3D 之上，这正是最不能丢的能力。

**⑤ 用 `flutter_scene` 的完整能力（物理 / 粒子 / glTF）。**
见决策 2。多用的每一项都是独立的升级与回归面，而本需求不产生 3D 模型资产。
