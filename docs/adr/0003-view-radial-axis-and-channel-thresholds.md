# ADR-0003 · 宇宙视图的径向语义与三处通道判据

- **状态**：已接受
- **日期**：2026-10-17
- **决策人**：liberal

## 背景

`B2` 收尾时，`STD` §五 挂着三条「`B3` 前定」的待办：`r` 的复合轴没定义、「主取值」没有承载位、「指向未知」没有视觉表达；另有 `φ` 的深度归一化缺口径。四者都指向同一件事 —— **`SPEC-VIEW-002` 只说「三维坐标各承载一个维度」，但没说 `r` 是哪一维**。

`SPEC-VIEW-002` 原文写「`r` = 复合轴（7 段径向分层）」。**全仓没有第二处解释「复合」由哪几维合成**：`SRS` 只重复了一句「各承载一个维度」，`channel-table` 管通道不管坐标。因此这不是「查一下就能补」的缺口，而是必须重新裁定。

裁定前做了三组实算（α 包 150 项 / 170 边，`content/python/dist/pack.json`），结论见各决策。

## 决策

### 1. `r` = 域带，段数 = 空间域数（替换「7 段」）

同一空间内按 `manifest.domainIds` 顺序等分，`r = (域序号 + 0.5) / 域数`（`C-30` 的公式不变，只把常量 7 换成域数）。

**Z0 边界**：跨空间时先按 `manifest.order` 分层、层内再分域，同一空间不跨层。
**Z2 起**：`r` 恒等于该域带，不再分担定位职责 —— 域即根，属正常退化，不是缺陷。

**理由（两条实算）**

1. **α 包里没有任何单维能分 7 段**：`layer` 3 值（143/4/3）· `type` 4 值（78/63/6/3）· 连接度 4 值（1–4）· `k` 4 个取值 · `domainId` 10 值（15×10，完美均衡）。
2. **任何二维交叉最多 6 个非空格**：`type×tacit`、`layer×tacit`、`type×layer` 都是 6，且 `type×layer` 前两格占 137/150（89%）—— 映射到径向会挤成两团、其余四段细如发丝。

而 `Item` 九个字段里，只剩 `type` 与 `domainId` 未被任何通道占用（`layer`→形态 · `requirements`→亮度/虚实 · 连接度→大小 · `sixAxis`→颜色/`θ` · 边→边样式 · `mastery`→轨道环 · SRS→脉动）。`type` 又与虚实通道**完全共线**（见决策 2），故只剩「域」。

**顺带的好处**：三个坐标变成正交且语义清晰 —— `r` = 哪个域（容器）· `θ` = 六轴（分类）· `φ` = 前置深度（顺序）。

### 2. 虚实判据 = 不可外化格 ≥ 3（`C-34`）

**理由**：α 包的不可外化只有三档，中间没有别的情况 ——

| 不可外化格 | 项数 | 组合 |
|---|---|---|
| 0 | 37（24.7%） | 无 |
| 1 | 110（73.3%） | **恒为 `tacit`** |
| 3 | 3（2.0%） | `boundary + proposition + tacit` |

`≥ 1` 会让 113 项（75%）变虚，虚化从「例外」变成「常态」，通道失去区分力；`≥ 2` 与 `≥ 3` 在这份数据上**完全等价**（2 格的项不存在）；取 3 是唯一配得上「高比例」措辞、且能圈出群体的值。

**语义验证**：命中的 3 项是「组合优于继承」「宽恕与许可（EAFP/LBYL）」「线程 / 进程 / 协程选型」—— 三件公认靠经验判断、写不成条文的事。

**同时发现一处共线**：这 3 项正好是 `type = tacit` 的全部（两处标注一字不差）。故 `type` **不得再占用其它通道**，否则同一个事实会被表达两次。

**已知代价**：通道在 α 包上只亮 3 个点（2%）。这是内容侧标注密度问题（`tacit` 格 73% 的项都有），登记给内容侧 v0.2，**不得靠放松阈值解决**。

### 3. 新增 `Item.primaryAxis`（第 4 次扩 schema）

`channel-table` §一 #5 明文要求「按主取值着色，**声明式指定，不按优先级猜**」，而 `sixAxis` 是「六键各单值」的 object，没有主从关系。

| 被否方案 | 为什么否 |
|---|---|
| 用 `manifest.sixAxis` 的轴序，首轴为主 | 「取顺序第一个」正是规格排除的「按优先级猜」；且 `manifest.sixAxis` 是空间级声明，不是项级 |
| 运行时按「该轴取值在空间内的稀有度」推 | 改内容就换色 —— 同一项颜色不稳定，与「位置即语义」要求的确定性相冲 |

**代价如实记录**：这是第 4 次扩 schema，而 `SPEC-VIEW-025` 已把第 3 次称作「扩 schema 的临界点」。但颜色与 `θ` 扇区都等这一个字段，不给它，宇宙视图只能继续用域序号占位（当前 `scene.dart` 的状态）。须登记为 `PACK` 的 B 级变更，内容侧补值。

### 4. `φ` 的径向位置 = 累计项数分位（**改掉了「分段折叠」**）

`SPEC-VIEW-002` 只写「`φ` 越深越靠外」，没写怎么归一。α 包的 `φ` 铺到 **63 层**、0 层只 3 项，等距展开会把层间距压到 `~0.025`，深层必然粘连。

**原方案是分段折叠（0–9 展开、≥10 收成一条「深层带」），实测否掉了它**：`φ ≥ 10` 的层装了 **126 项（84%）** —— 把 84% 的项挤进一条细带，折叠本身就是新的粘连源。任何一个固定阈值都救不了，因为尾部 54 层平均每层只 2.3 项。

**改为**：径向位置取**该层起始项的累计分位**，`r_φ = 累计在前项数 / 总项数`。半径正比于项数，密度自然均匀；0 层那 3 项落在 `r_φ ∈ [0, 0.02)`，符合「根在中心」；也不需要「另有 N 层」这类计数。

> 这条与 `SPEC-VIEW-008`（深链空间首屏只到 `φ=2`）不冲突：那条管的是**树的展开深度**，这条管**宇宙的径向位置**。

### 5. 「指向未知」沿用 `SPEC-VIEW-007` 的黑洞，不新增线型

`channel-table` §一 #6 把「弱依赖」与「指向未知」都记虚线，但后者端点不在册、画不出线（170 条边里 3 条被跳过）。**宇宙视图沿用树视图已有的黑洞**：缺失端画虚线占位节点（父位取「指向它的边的源点质心」），边指向它。

理由：`VIEW-007` 已经把「有痕迹无实体」做成了虚线占位 + 质心定位；跨视图沿用同一套视觉语言，比发明第三种画法省掉一次「一通道一维度」的豁免申请。

## 影响

- `SPEC-VIEW-002` **原地修订**（原句保留，表下加修订注记，不改编号、不新增 `SPEC`）—— `SPEC` 总数仍 171，`SRS` 的 128/81 切片计数不受影响。
- `channel-table` §一 #4 / #5 / #6 的判据补明文（本表是通道映射的唯一权威处）。
- `entity-fields` `Item.primaryAxis`；`constants` 新增 `C-34`。
- `STD` §五 第 8–10 项（主取值缺承载位 / 指向未知无视觉 / `φ` 无归一）可标闭环。
- **内容侧待办**：包 schema 加 `primaryAxis`（`PACK` B 级变更）；提高默会类标注密度（当前 2%，`tacit` 格标注过宽）。
- **未动**：`θ` 扇区的递归区间分割口径（`VIEW-002` 原文已写「含轴内递归区间分割」，`B3` 实现时细化）；窗口尺寸自适应（归 `ADR-0002` 修订二）。
