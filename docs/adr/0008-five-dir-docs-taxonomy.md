# ADR-0008 · 文档目录换轨：六目录并为五目录，`deliverables` 原位

- **状态**：已接受
- **日期**：2026-10-22
- **决策人**：liberal
- **覆盖范围**：`docs/` 下 `deliverables/` **以外**的全部活文档（5 个目录、**40 份**，含本 ADR 自身）的落点；[`.swe-init.json`](../../.swe-init.json) 的 `docsProfile.dirs`。**不影响**交付物的位置、命名与版号规则

## 背景

### 一、账本与实物已经不一致

`.swe-init.json`（`#114` 入库）写定 `docsProfile`：

```json
{ "id": "swebok-v4", "rev": 1, "dirs": ["decisions", "intent", "ideas", "specs", "runbooks"] }
```

而仓内实际是 `adr/` `design/` `reference/` `guides/` `readme/` `deliverables/` 六目录。账本进版本控制后，这句话不再是可以慢慢对齐的推断值，而是**有版本号的既成事实** —— 要么改账本，要么改目录。

### 二、六目录不是「名字不好看」，是分类标准打架

| 症状 | 实证 |
|---|---|
| `reference/` 一个目录装四类东西 | [`docs/README.md`](../README.md) 描述它需要 5 个顿号：「横切七表 + 未决台账 + 两份规格 + 两份方法论长文，共 12 份」。**一个目录的定义要靠枚举才说得清，说明它不是一类** |
| `guides/` 名不符实 | 3 份里 2 份是**规范**（`git-conventions` 定提交与评审、`dependency-licenses` 定许可判定），只有 `environment` 是操作。叫「指南」却大半是「规则」 |
| `design/` 与 `adr/` 的边界在实操中被反复推翻 | `not-list` 记「已裁不做 + 理由」，`open-decisions` 记「未裁待定」—— 两样都同时是「是什么」和「为什么」，按现有判据无法归位，只能塞 `reference/` 当台账 |
| `readme/` 不是文档类别 | 它是仓根 README 的**语言副本**，不承载新内容。放进 `docs/` 使它看起来像文档体系的一层，逼得 `docs/README.md:19` 专门写一段说明「它不参与判据」—— 需要一条例外规则，即分类失败的信号 |

`docs/README.md:17` 的现判据是「是什么/为什么 → `design/` 或 `adr/`；多少次/哪些值 → `reference/`；怎么操作 → `guides/`」。它按**文档的写作形态**分类，不按**读者要解决的问题**分类。前者的后果是：想知道「`not-list` 里有没有我要做的功能」，得先知道它属于「是什么」还是「为什么」。

## 决策

### 1. 五个目录，每个目录一个词能定义

| 目录 | 一句话定义 | 判据（放进来之前问自己） |
|---|---|---|
| `specs/` | **应当如何** | 它是可执行、可验收的规范吗？有值、有字段、有规则、有断言？ |
| `decisions/` | **定没定** | 它记录的是「已经这么定了」还是「还没定」？两者都是决策轴 |
| `intent/` | **为什么** | 它是论证与依据，且**不随实现改动**？ |
| `ideas/` | **还没认定的想做什么** | 它是候选、还没被接受成决策或规格？ |
| `runbooks/` | **怎么把东西跑起来** | 它是操作步骤或已知的坑，读它的人正卡在某个动作上？ |

加上不参与这套轴的一个：

| 目录 | 定义 | 为什么单独 |
|---|---|---|
| `deliverables/` | **要签字、有版号的交付记录** | 它按 `vX.Y.Z` 独立递增，而上面五个是活文档、不设版号。分类轴不同（版本 ≠ 内容），不能并进同一套判据 |

### 2. `intent` 与 `ideas` 的边界（唯一一处容易混）

**`intent` 是「已经认定的为什么」，`ideas` 是「还没认定的想做什么」。**

判据是**时态**：这条内容有没有被接受过？

- `intent/` 里的内容被引用时，是作为依据引用的（「因为 ADR-0005 的论证如此」）
- `ideas/` 里的内容被引用时，是作为候选引用的（「这里有个想法，还没定」）

`ideas/` 目前是空目录，但要建 —— 空目录本身就是信息：**目前没有悬而未决的候选**。里面只放一份 `README.md` 说明这个判据。

### 3. `deliverables/` 原位不动，动它与本 ADR 解耦

三条理由，按强度排序：

1. **它属另一根轴**（版本轴），本 ADR 换的是内容轴。混在一笔改动里，失败时无法二分定位
2. **搬动成本被实测过**：`app/tool/docs/rules.dart`（1182 行）里有 **9 处**路径硬编码 —— `docFiles`（4 份）· `versionDocFiles`（6 份）· 6 个单文件常量 · `itemIdToFile` 表。改漏一处 CI 立刻红
3. **它对版号有外部约束**：GB/T 8567 的六段分类是外部标准，不是本仓自定的

**时点：`S6` 换轨收尾之后，到 `S7` 再决定动不动。** 若将来要动，前置两件事必须先做：① 把 9 处硬编码收敛成单点（路径配置化，与换轨无关、可独立做）；② 在 `SCMP` 登记配置项标识变更 —— 路径属配置管理对象，**不写进每份交付物的变更记录**（那是内容变更记录，混进去会让人误以为文档内容改过）。

## 被否方案

### A. 维持六目录，改账本去迁就实物

改动最小，零链接改写。

**否掉的理由**：账本是 `swebok-v4` profile 的一份实例，改它等于宣称「本项目不采用该 profile」，那要连带解释为什么当初选它。而上一节的四条症状说明六目录本身的分类标准就有问题 —— 改账本只是把问题藏进版本历史。

### B. 六个目录全并进五目录，`deliverables/` 也搬

**否掉的理由**：`specs/` 里躺着一批 `vX.Y.Z` 文档，就与「活文档不设版号」直接矛盾 —— 这条红线写在 [`AGENTS.md`](../AGENTS.md) §28。而把 26 份交付物移出 `docs/` 到仓根，等于让仓根承担两套版号纪律。分类要好，但不能拿已定的纪律去换。

### C. 只改名不拆分（`reference/` → `specs/`，其余同理）

一次改名即可，不需要逐份判定。

**否掉的理由**：`reference/` 12 份四类混装是本轮问题的**主因**，改名只是把「12 份靠索引解释」换成「12 份靠新目录名解释」，读者的检索路径没变。而且 `not-list` / `open-decisions` 留在 `specs/` 里，会让 `specs/` 同时承担「规范」与「决策」两种时态。

### D. 按 Diátaxis 四分（tutorial / how-to / reference / explanation）

业界成熟分类，有明确文档。

**否掉的理由**：Diátaxis 没有「**决策**」这个位置 —— 它假设文档描述的是现状，而本项目的 `not-list`、`open-decisions`、`ADR` 记的是**裁定的历史与未决项**，属第四类之外的东西。硬套会让决策类内容被塞进 `explanation`，与 `intent/` 的论证混在一处，又回到「时态不清」的老问题。

### 预演只模拟单批，不能累加，也不能提前采信后面的批

`migrate_docs.dart --batch N` 是基于**当时磁盘的实际布局**算的，只应用第 N 批的映射。因此：

- 四批预演的条数**不能相加**（同一文件在不同批的「当前布局」不同）；
- 批 3 的预演结果，在批 2 真正执行后**必须重跑**才能作为执行依据 —— 例如批 5 的 readme 搬家会把 `../../docs/design/...` 算成 `docs/design/...`，而批 3 执行后那个路径已经不存在；
- **纪律：每批执行前重跑一次 `--batch N --diff`，逐条看到 `+` 才对得上。**

批 0 的四批预演只证明两件事：脚本能跑通、各批映射表自洽（源文件齐全、目标不冲突）。

### 三处目录级链接无法自动改写，必须人工就地改

预演把它们单独列为 `MANUAL`（映射表能把「一个文件」映到「一个文件」，无法把「一个目录」映到「四个目录」）：

| 批 | 位置 | 链接 | 搬完后为什么断 |
|---|---|---|---|
| 2 | `docs/README.md:14` | `[adr/](adr/)` | `adr/` 全空，git 不留空目录 |
| 5 | `docs/README.md:13` | `[guides/](guides/)` | `guides/` 三份全部搬走 |
| 5 | `docs/AGENTS.md:42` | `[readme/](readme/)` | `readme/` 五份移到仓根 |

这三处**在该批内就地改**，不能留到批 6 —— 否则那一批的 `main` 会红。

- **`docsProfile` 的账本状态待清**：本 ADR 追认了 `docsProfile.dirs`，但 `.swe-init.json` 的 `inferredFields` 里仍列着 `docsProfile`。是移除该项（改为已确认）还是保留，由决策人另定 —— 本 ADR 不代改账本。
- **`docs/` 的文档数会从 66 变 61**：`readme/` 5 份移到仓根，不再计入 `docs/`；换轨后分布为 `decisions` 11 · `specs` 21 · `intent` 2 · `ideas` 0 · `runbooks` 1 · `deliverables` 26。
- **`ideas/` 是唯一空目录**，只需一份 `README.md` 写清「想法 vs 意图」的时态判据（见决策 §2）。它不计入上表的 61 份。
