# ADR-0005 · 三轴容器树取代六轴坐标

- **状态**：已接受
- **日期**：2026-10-20
- **决策人**：liberal
- **覆盖范围**：`SPEC-FND-002`（六轴坐标）· `SPEC-FND-006`（坐标 vs 容器）· `SPEC-FND-007`（一空间一包）· [`ADR-0003`](0003-view-radial-axis-and-channel-thresholds.md) 的径向语义前提 · [`ADR-0004`](0004-accounts-as-usage-prerequisite.md) 的「账号为使用前提」（**收窄**，见决策 6）

## 背景

`SPEC-FND-002` 的原文裁定是：

> 六轴（学科 / 岗位 / 行业 / 能力 / 主题 / 技术栈）是**索引坐标，不是嵌套层级**；轴与轴之间没有上下级。「计算机 → 编程语言 → Python」是三次连续筛选，**不是三次下钻**。

`SPEC-FND-007` 配套裁定「一空间一包，客户端按空间加载，**不加载全量**」。

2026-10-19/20 的连续讨论得出新需求：本体是**三轴七级树 + 3D 宇宙空间**，结构同构于真实宇宙；学科 / 专业 / 角色三条轴是可逐级下钻的容器树，跨轴关系由**虫洞**缝合。这与上述两条裁定正面冲突 —— 不是「补充几个字段」，而是**地基互换**。

冲突的实质不在措辞，在于「点击」这一动作的语义：旧裁定里点击是**写筛选条件**（换根），新需求里点击是**下钻到子节点**（改地址）。这两种语义不能共存于同一层。

## 决策

### 1. 三轴成为容器树，四类降为标签

| 旧 | 新 |
|---|---|
| 学科 / 岗位 / 行业 / 能力 / 主题 / 技术栈（六轴平权） | **学科 / 专业 / 角色** 三棵容器树 + **行业 / 能力 / 主题 / 技术栈** 四类标签 |

「专业」在旧六轴里**不存在**，是新增的第三条容器轴（来源：普通高等学校本科专业目录 2025，12 门类 / 93 类 / 845 专业）。

**判据（本 ADR 的核心可复用结论）**：

> 能成为**容器轴**的，必须有官方法定分级编目，且满足**唯一父级**；否则只能作为**标签**。

学科（研究生教育学科专业目录 2022）· 专业（本科专业目录 2025）· 角色（职业分类大典 2022）三者满足；行业 / 能力 / 主题 / 技术栈不满足（无权威分级编目，且跨轴横切、给不出唯一父级）。

### 2. 骨架到恒星，载荷从恒星以下开始

- **骨架包**：全量内置，覆盖根 → 恒星槽位（**3,323** 节点，压缩后数百 KB），不走插件、不进审核
  > ⚠️ **2026-10-20 勘误**：原文写「≈3,929 节点」。其中学科轴的 676 个「二级学科」**没有任何单一数据源可支撑**（研究生目录只到一级，二级由学位授予单位自设；676 恰等于 GB/T 13745 的二级学科数，但那份标准的 62 个一级与研究生目录的 117 个一级不同源）。规模随之定稿为 3,323，推导与三轴数据源见 [`skeleton-catalog.md`](../reference/skeleton-catalog.md)
- **载荷包**：提供行星系 / 行星，**可带子树**（恒星 → 行星系 → 行星，深度封顶两级），按需装载
- **`Pack.kind` 五类**：`skeleton` / `payload` / `overlay` / `terrain` / `method`（`skeleton` 内置 ⇒ 插件标准覆盖其余四类）

`SPEC-FND-007` 的「一空间一包」**限定到载荷包**，并新增骨架包例外。旧的错不在「一空间一包」，而在于它假设只有一种包。

### 3. 虫洞边三类单值，只影响呈现

`same_name`（同名异编）/ `granularity`（粒度错位）/ `many_to_many`（M:N 共享），单值，判定顺序 `same_name > many_to_many > granularity`。

不采用多值数组：三形态本身会重叠（`0812 ↔ 080901` 既像同名异编又像粒度错位），多值等于把「这条边画成什么样」的矛盾推给渲染层。

### 4. 地形独立成第四类包，`⪯` 收窄为 required 边的传递闭包

先修边（A 是 B 的前置）不在任何官方编目里，且**跨轴**（`Python → 框架调参` 同时涉及学科轴与角色轴），因此独立成 `terrain` 包，与载荷包同级、各自版本。

`PrerequisiteEdge.strength ∈ {required, recommended}`：**只有 `required` 构成 `⪯`**，`recommended` 仅影响排序建议与提示、不构成可达性约束。`SPEC-STEP-003` / `007` / `021` 三处全部改挂地形 DAG，**全项目只有一套偏序源**。

### 5. 事件边界划三区，`X-04` 的适用范围收窄

| 区 | 内容 | 是否走事件 |
|---|---|---|
| 只读分发区 | 骨架 / 载荷 / 地形 / 方法 / 覆盖包正文 | 否 |
| 可写内容区 | S4 自建节点 · 个人 `OverlayPatch` · `PathClaim` 墓碑 | 否 |
| 事件日志区 | 学 / 评 / 复习 / **访问** | **是**，append-only |

判据不是「谁产生的」，而是**「是事实的累积（内容）还是事实的投影（行为）」**。

因此 `X-04` 的适用范围由「事件是唯一事实源」收窄为「**学习状态**以事件为唯一事实源」。连带：原定新增的 `AddressLog` 实体**取消**，降级为 `navigate` 事件的 fold 投影；`SrsState` 同样为投影（其原文已标「派生，由事件折叠」，与本决策一致）。

### 6. `ADR-0004` 由「使用前提」收窄为「云能力前提」

| 能力 | 是否需要账号 |
|---|---|
| 本地浏览、学习、复习、自建内容 | **不需要** |
| 跨设备同步 · 市场安装 · 机构 / 团队作用域 | 需要 |

`ACC` 与 `SYNC` 两份文档不删任何内容，只把适用范围从「全体用户」收到「需要云能力的用户」。`v0.1.0`（`P1`）为纯本地，无账号、无服务端。

### 7. 身份与地址分离

`id` 稳定不变，`path` = 当前位置，URI = path。虫洞、覆盖锚点、引用全部指向 `id` ⇒ 改名、改主父不动地址。

## 被否方案

**① 保留六轴，把三轴作为「视图」叠加。**
六轴既非容器也无编目，叠加后同一层会同时存在「可下钻」与「不可下钻」两种点击语义，用户在界面上无法预判点下去会发生什么。

**② 六轴全保留 + 三轴新增（九轴并存）。**
`FND-002` 的「同轴多选取 OR」前提是轴内单值；九轴会让筛选组合爆炸，且四类无编目的轴给不出候选值域 —— 它们的值只能手工填，跨包不可比。

**③ 完整保留旧 `⪯`，地形 DAG 另算。**
两套偏序会得出互相矛盾的结论：同一项可能在 `STEP-003` 下「可学」而在 `STEP-021` 下「前置缺」。这是最难排查的一类 bug。

**④ `AddressLog` 保持独立状态表。**
与 `X-04` 正面冲突，且跨设备合并时要在事件流之外另写一套合并逻辑。

**⑤ 让载荷从星系群层（L3）起自带下级结构。**
会造成同一节点两处定义，虫洞与 `base_hash` 锚点立即分裂；骨架已含恒星层，插件再提供等于在 `S1` 里造一个与 `S0` 同名的节点。

**⑥ `MethodProfile` 继续硬编码为平台内置。**
一份配方要服务多个载荷包（N:M），硬编码下只能复制代码；独立成包是唯一能表达这个关系的形态。
