# `path` 规则（16 条）

> **本文件的来历（必读）**：此前四份文档都写「path 的 16 条规则见**插件标准**」，而该文档**不存在**（2026-10-20 实测：全仓 `grep "插件标准"` 3 处命中，全为引用、零定义）。本文件是这 16 条的**成文版** —— 由既有已裁文档**推导**而来，逐条标 `src:`；**不是**那份口头约定的原文。凡与 `src:` 所指文档冲突，**以 `src:` 为准**并回来改本表。
> **为什么必须成文**：`B13a` 笔 2 的出口判据要求「`id` / `path` / URI 三元与 **path 16 条校验器**」。判据要求实现的东西，其定义必须先存在 —— 否则校验器只能自造规则再自判通过（`X-05`）。
> **单一事实源**：16 条的**编号与表述**只在这里；其余文档引用本文件，不复制条目正文。

## 一、构成（1–5）

| # | 规则 | `src:` |
|---|---|---|
| **P-01** | **`path` 是派生值，不是字段** —— 由父链 `slug` 串联、运行期 `pathOf(node, parentIndex)` 计算。任何实体、包、事件、索引都**不得存储 `path` 快照**；引用一律用 `id`（虫洞 / 覆盖锚点 / `attach_to` / `catalog_refs` 全同）。**身份与地址分离**：`id` 稳定不变，`path` 只是当前位置 | `ADR-0005` 决策 7 · `ADR-0007` 决策 2 · `entity-fields` §2 |
| **P-02** | **`path` = 从轴根到本节点的 `slug` 序列**，以 `/` 连接，无前后导斜杠。首段是轴根（三轴各一个：`discipline` / `major` / `occupation`）。同子树内**段数 = 该子树层数**；官方子树与编外子树段数可不同 | `entity-fields` §2 · `skeleton-catalog` §五 |
| **P-03** | **URI = `path`**。不存在第二套地址编码；改名即改 URI，旧 URI 靠 `PathAlias` 重定向（见 P-10 / P-11） | `ADR-0005` 决策 7 |
| **P-04** | **`slug` 字符集 = `^[a-z0-9-]+$`**（小写字母、数字、连字符）。下划线开头的段为**保留段**（如 `_extra`），只允许系统生成，作者不可自取。全角 / 半角括号、连接符、异体字必须在生成前归一到该字符集 —— 目录 PDF 抽取在这些字符上必然有偏差 | `entity-fields` §2 · `skeleton-catalog` §六 步骤 2 |
| **P-05** | **行星系与行星无官方码，`slug` 是它们唯一的 path 段来源**；骨架恒星段由 `official_code` 派生稳定 slug（**改名不改码**，故也不改 id） | `entity-fields` §2 · `skeleton-catalog` §四 |

## 二、唯一性（6–8）

| # | 规则 | `src:` |
|---|---|---|
| **P-06** | **同父唯一**：同一 `(parent_id, slug)` 在全库至多一个 `live` 节点。这是「同父唯一」的**唯一判据形式** —— 不比 `name`（可重名）、不比 `id`（id 必唯一，比它无意义） | `skeleton-catalog` §五 步骤 3 · `entity-fields` §2 |
| **P-07** | **`path` 全局唯一**。它由 P-06 + P-02 归纳得出（三轴根唯一 ⇒ 父 path 各不相同 ⇒ 子树前缀不同），但**必须独立断言** —— 校验器不能只实现 P-06 就假定全局唯一，否则跨轴同名 slug 造成的拼接重合无人拦 | 由 P-02 + P-06 推导 |
| **P-08** | **两条唯一性通道分开**：骨架 `path` 由**构建过程一次性**保证唯一，运行期不再维护账；**插件节点**走 `PathClaim`（`path` / `node_id` / `state`）。合并成一套会让「骨架升版」与「插件装载」互相等锁 | `entity-fields` §6 |

## 三、变更与重定向（9–12）

| # | 规则 | `src:` |
|---|---|---|
| **P-09** | **`id` 稳定、`path` 可变**：改名或改主父**只改 `path`**，不产生新 `id`、不产生新节点、不丢已学事件。`id` 不带版本号（带了则升级后所有历史事件指向旧 id） | `ADR-0005` 决策 7 · `entity-fields` §2 |
| **P-10** | **`slug` 变更 ⇒ 写 `PathAlias{reason: slug_change}`**（`from_ver` / `to_ver` 可空 —— 改名发生在骨架版本轴**之外**），旧 path 重定向到现役 `node_id` | `entity-fields` §7 |
| **P-11** | **改主父 ⇒ 写 `PathAlias{reason: parent_change, from_ver, to_ver 必填}`** —— 骨架升版改主父是**版本轴内**变更，两个版本号必须写得出，否则「哪一版之后该地址指到新父」无从判定 | `entity-fields` §7 |
| **P-12** | **`PathAlias` 禁止成链**：写入 `A → B` 时若 `B` 已有 alias 指向 `C`，**直接把 `A` 改指 `C`**。解析只需一跳 ⇒ 不可能成环，也不需要环检测 | `entity-fields` §7 |

## 四、解析与墓碑（13–14）

| # | 规则 | `src:` |
|---|---|---|
| **P-13** | **解析顺序固定**：`live` → `tombstone`（命中即报「此地址已停用」）→ `alias` 重定向。**顺序不可换** —— 先查 alias 会让「已复用的旧地址」盖掉现役节点，症状是访问新节点却打开旧内容 | `entity-fields` §7 |
| **P-14** | **墓碑永不复用**：卸载插件**只删节点、不删 `PathClaim`**，`state` 转 `tombstone` 并保留。否则「A 卸载 → B 装上 → A 再装回」时 A 会以为自己是首次占用，两个包共用一个 path | `entity-fields` §6 |

## 五、跨包边界（15–16）

| # | 规则 | `src:` |
|---|---|---|
| **P-15** | **禁跨包父子**：一个 `Node` 的主父必须与它**同包**（`pack_id` 相同）。跨包挂载只能走 `WormholeEdge`（引用）或 `payload.attach_to`（挂到骨架恒星下，那是**骨架包**的节点，属显式例外且只有这一个方向）。`attach_to` 装包时**物化为一条跨包 `main` `ParentEdge`**，之后按普通主父处理 —— 不物化则 `pathOf` 与 `ParentIndex` 要各存两种父来源 | `SDP` §4.2 `B14` · `ADR-0005` 决策 5 · [`minimal-pack.md`](minimal-pack.md) §4.1 |
| **P-16** | **装包前以 `manifest.path_reservations[]`（`(parent_id, slug)` 清单）判冲突** —— 侧载无审核，这是**唯一**依据。不得装完再靠遍历全树比对（那在 3,323 骨架 + 多载荷下既是性能问题，也来不及回滚） | `entity-fields` §1 · §6 |

## 六、与校验器的对应

`B13a` 笔 2 的三元校验器（`id` / `path` / URI）**逐条对应**：

| 校验项 | 覆盖条目 | 可观测断言 |
|---|---|---|
| `id` 格式与唯一 | `P-05` · `P-09` | `{plugin_id}:{local_id}` 或 `skeleton:{local_id}`；全库无重复；无版本号段 |
| `path` 构成 | `P-01` · `P-02` · `P-03` | `pathOf` 与 `id` 无耦合；段序列 = 父链 slug；URI 与 path 逐字相等 |
| `slug` 形态 | `P-04` | 正则全绿；`_` 前缀只出现在系统生成 |
| 唯一性 | `P-06` · `P-07` | 同父无重复；全局无重复 |
| 重定向闭环 | `P-10`–`P-13` | 每条 alias 一跳可达、无链、解析顺序可观测 |
| 墓碑 | `P-14` | 卸载后 claim 仍在 |
| 跨包 | `P-15` · `P-16` | 跨包主父被拒；reservations 命中即拒装 |

**P-01 与 `P-07` 是两条最容易被「实现成一半」的**：P-01 的常见错法是给 `Node` 加一个缓存 `path` 字段（性能考虑），一旦存下来就有两份真相；P-07 的常见错法是只写 P-06 就宣称唯一性已保证。两条都要有独立断言，不能靠「代码里看着对」。
