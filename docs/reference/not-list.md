# NOT 清单（明确不做的事）

> **为什么单列**：「做什么」写了，实施者仍可能把「不做什么」当成遗漏去补。「不做」的判断必须落纸，**理由才是它挡得住人的东西**。
> **与「明确不管」的区别**：「不管」是**职责边界**（这件事归别人管）；「不做」是**产品取舍**（永远不做）。
> 本清单条目**不占裁定编号**；新增条目须带一句理由，且经评审。

## 一、已裁定不做（永久）

| # | 不做的事 | 理由 | 若做了会怎样 |
|---|---|---|---|
| N-01 | **3D 力导向布局** | 位置即语义 —— `r`/`θ`/`φ` 三个坐标各承载一个维度，力导向会把位置变成纯装饰，可读性归零 | 六轴、`⪯`、层号三个维度全部失去视觉表达，宇宙退化成一张无信息量的星图 |
| N-02 | **双向笔记同步** | 双向等价于在 HLC 之外**再造一条因果链**；两套定序语义并存时「哪边是真相」永远没有答案 | 冲突合并、ID 映射、第二套时钟全部引入，成本高一个数量级，且事件溯源出现第二个真值源 |
| N-03 | **Planner 显示难度分布** | 建计划时**一项都没学过**，`D` 要首次评分才初始化，此刻确实没有数据 | 只能靠 pack 声明先验难度（作者编的）或用 `φ` 代理（不同构），两种都会误导用户 |
| N-04 | **推荐引擎 B 级（一键生成 Plan）** | 首期无数据可依，只能靠 L 级与逆序数，而那正是 A 级排序；且系统推荐逆序体系会与「由用户决定代价」冲突 | 要么退化成 A 级套一层黑箱，要么隐式禁掉逆序体系，把「不禁止但标代价」改成硬禁 |
| N-05 | **打卡项毕业** | 出口问的是「能不能用」，打卡没有可观测证据；`S` 永不增长 ⇒ 永不到 180，这是 M3 与 X2 相乘的必然结论 | 给出口开后门 —— 点足够多次「已完成」即可毕业，`S ≥ 180` 当场失效 |

## 二、已裁定不做（阶段性，翻转须走评审）

| # | 不做的事 | 理由 | 翻转条件 |
|---|---|---|---|
| N-06 | **笔记双向回流（含「手动拖回覆盖」）** | 手动覆盖等于对事件流做非事件化写入，破「事件是唯一事实源」 | 回流本身记成 `note_revised` 时，即已接近双向，须走 ADR |
| N-07 | **跨空间统一队列** | 跨空间比 `due` 是**伪排序**：短周期项（单词 1–7 天）会永久压制长周期项（异步 20+ 天）；且「20 个复习名额怎么在两个空间之间分」无客观依据 | 需要先定义跨空间配额的客观依据 |
| N-08 | **首期实现 `Item.aliases`（别名 / 拼音匹配）** | 会第三次扩大 schema 冻结范围（前两次是 `questions` 与 `excerpts`），且落在关键路径上 | 二期；同时解掉「重复检测靠别名」的降级状态 |
| N-09 | **首期自然语言（LLM）定位** | 破 M2a 离线闭环；D6 已把 NL 排在第三期。首期用纯规则能吃下大多数真实输入（**输入框为主 + 表单兜底**） | M4+ 按 D6 三期规划推进 |
| N-10 | **「不承诺防作弊」之外的反作弊措施** | 系统只能约束它观测得到的（点看答案、离开题目页）；翻书、问人无法观测 | 不翻转 —— 这条是**诚实边界**，不是技术限制 |
| N-11 | **新增第六视图（能力清单 / 笔记独立成视图）** | 底部导航会从 Z0–Z4 的**视距刻度**退化成功能标签栏；且自建笔记无锚点，独立视图里两套对不齐 | 需要先解决「视图 = 视距」这一语义 |
| N-12 | **给自建粗项「补光」** | 六要件全空 ⇒ 亮度极低 ⇒ 表现为暗星，这是**正确表现**；补光会让「未声明即不渲染」与亮度通道同时失效 | 不翻转 |
| N-13 | **在树视图保留六轴罗盘** | 罗盘承载 `θ` 扇区方位，二维树没有方位，保留即成假控件 | 不翻转；树视图筛选走 ② 尾部「+ 筛选」平铺面板 |
| N-14 | **笔记进入量化** | 改笔记能改掌握度 = 第二个刷分后门（与已封顶的打卡同族）；`d` 只看六要件 | 不翻转 |

## 三、方法层：可自建但不可自创的部分

「方法可自建」有硬边界 —— **能自建的是配方，不是机制**：

| 可自定 | 不可自定 |
|---|---|
| 步骤数 · 先后 · 循环 | **执行算子本身**（6 类之外不得新增） |
| 每步的完成判据与参数 | 事件类型与日志结构 |
| 步骤的 `phase`（可覆盖派生值） | SRS 时钟 |
| 是否有 `hint` | 进度 / 掌握度的计算口径 |

**理由**：算子是可执行、可记日志、可纳入进度的最小单位。允许自创步骤语义 = 新造一个引擎无法识别的动作 ⇒ 日志记不下、进度算不出、调度无从下手，「零核心代码改动接入新方法」当场失效。

## 四、本清单的维护

- 新增条目须说明：**不做的是什么 · 为什么不做 · 若做了会怎样**（缺第三项则不收）。
- 条目从「阶段性」转「永久」或反之，须在 PR 中显式声明并在 `adr/` 留痕。
- **实施者遇到「为什么没有 X」时，先查本清单**；不在本清单里的，才是真的遗漏。
