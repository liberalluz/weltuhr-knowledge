## 一、理论地基

### SPEC-FND-001 KST 三元组
**裁定**：全案以 KST 三元组为理论地基 —— 知识项 `Q`、学习者状态 `K`、前提偏序 `⪯`。三者缺一不可：只有 `Q` 是词表，只有 `K` 是学习记录，只有 `⪯` 是目录。**产品的全部能力都建立在这三者的联合之上。**
`src:` 方法论 §1 · 第 1 轮

### SPEC-FND-002 六轴是索引坐标，不是嵌套层级
**裁定**：六轴（学科 / 岗位 / 行业 / 能力 / 主题 / 技术栈）的每个取值是**标签**，不是文件夹。一个知识项可同时带有多个轴值；轴与轴之间**没有上下级**。同一轴内，一个项**只取一个值**（这是「同轴多选取 OR」能成立的前提）。
**推论**：「计算机 → 编程语言 → Python」是**三次连续筛选**，不是三次下钻。
`src:` 第 26–30 轮 · `entity-fields.md` §2

### SPEC-FND-003 三层是径向属性，不是层级
**裁定**：`Item.layer`（持久 / 视图 / 快消）表达知识的**保鲜周期**，是项的属性，**不构成容器层级**。树视图的第一层用**域**，不用层；层在树里以**行尾标签**呈现。
`src:` 第 32–34 轮 · VIEW N-c

### SPEC-FND-004 六要件与三态
**裁定**：每个知识项有六要件 —— 边界 / 证成 / 命题 / 关联 / How / Tacit。每格三态：**齐 / 缺 / 不可外化**。
**「不可外化」是合法状态，不是缺陷。** 默会类知识本就不能完全外化；把它当缺失处理，会对语音、技能、默会类项产生系统性歧视（掌握度永久接近 0）。
`src:` 方法论 §4 · QUANT M2

### SPEC-FND-005 `⪯` 必须是 DAG
**裁定**：前提偏序 `⪯` 是**有向无环图**。内容校验阶段必须拒绝任何环。`⪯` 定义在**空间级**，一个空间只有一套 `⪯`。
**推论**：不得给空间内的某个域单独配一套排序 —— 那等于要求同一空间存在多套 `⪯`，「独立前提偏序」这条边界判据随之作废。
`src:` 第 1 轮 · PACK 边界判据 · PLAN

### SPEC-FND-006 坐标 vs 容器（关键辨析）
**裁定**：六轴是**坐标**（无边界、只筛选、可多重成立）；知识空间与域是**容器**（有边界、可进入、唯一父级）。两者的点击语义完全不同：

| | 坐标 | 容器 |
|---|---|---|
| 点击效果 | 写 `axisFilter`（只筛选） | 换根 / 进入 |
| 能否放内容 | 否 | 是 |

**上位层（计算机专业 / 编程语言）不升级为容器**，除非它自己持有 `Item`（如「计算机导论」这门课本身）。届时它与 Python 的关系是**平级**（两个空间），不是父子。
`src:` 第 26–31 轮 · glossary §二①

### SPEC-FND-007 一空间一包
**裁定**：内容分发的最小单位是**知识空间**，一空间一包。包边界由三条判据裁定（见 PACK）。客户端按空间加载，不加载全量。
`src:` PACK · 第 26 轮

## 二、定位与作用域

### SPEC-FND-008 定位三态
**裁定**：定位结果有三种状态，**衡量的是「定位是否成功」**：
- **有定位**：唯一命中，直接落点
- **部分命中**：多命中或命中上层，给候选
- **无定位**：命中集为空

> ⚠️ 三态与「无命中四类分诊」是**两套正交的东西**：三态判「成没成」，四类分诊处理「无定位之后怎么办」（见 VIEW）。
`src:` 方法论 · VIEW DT-6

### SPEC-FND-009 定位引擎与视图解耦
**裁定**：定位引擎只有一个，宇宙 / 树 / 详情 / 搜索是**同一份数据的四种投影**。引擎不知道也不关心结果在哪个视图里画。

## 三、事件折叠底座

### SPEC-FND-010 事件是唯一事实源
**裁定**：所有可写状态由 `fold(events, asOf)` 得出。**不得引入与事件流并行的可写状态表** —— 会话游标、笔记版本、掌握度快照、SRS 状态全部是派生值。
**判据**：如果一个状态既能从表读、又能从事件算，那就有两份可能不一致的真相。
`src:` 第 53 轮 · `event-types.md`

### SPEC-FND-011 混合逻辑时钟（HLC）
**裁定**：事件定序用 HLC `{physical, counter, deviceId}`。理由是 **M2a 已定离线闭环** —— 用户在没网时也要能写事件，服务端递增序号要求先连上才能定序，设备独立序号只能建偏序（而 FSRS 的 `D`/`S` 不可交换，必须全序）。
**实现约束**：物理时间由服务端 clamp 校正，逻辑计数保证不倒退。
`src:` GOV Z1

### SPEC-FND-012 事件只 append
**裁定**：合并、迁移、下线、回滚都以**新增事件**表达，不修改、不删除历史事件。孤儿项（包里已被删除的项）的事件**全部保留**，只标「已下线」。
`src:` GOV Z4 · `event-types.md`

### SPEC-FND-013 稳定的 `Item.id`
**裁定**：`Item.id` **必须与版本无关**。若 id 带版本号，包升级后所有已学事件都会指向旧 id，迁移（拆分 / 合并）与下线机制全部失效。
**这是事件溯源能跨版本成立的前提，属 pack schema 的硬性约束。**
`src:` GOV Z3 连带 · PACK

## 四、贯穿性判据

### SPEC-FND-014 未声明即不渲染
**裁定**：模型里没有声明的通道、字段、分区，界面不得凭猜测画出来。缺失必须表现为**空位**或**不画**，不得补默认值。
**形态变化**：笔记里「不可外化」格不是不画，而是画一个「需在实践中体会」的空位 —— 这是同一原则的两种表现，不是例外。
`src:` 第 20 轮 · `00-index.md` X-01

### SPEC-FND-015 声明驱动零分支
**裁定**：空间差异、语言差异、方法差异一律由**内容包与平台声明**承载，代码里不得出现「按具体空间 / 语言分支」的写法。
**这是 M3 验收标准「零核心代码改动接入新空间或新方法」的落点。**
`src:` 第 40–44 轮 · PLAN · STEP

### SPEC-FND-016 验证不得自证
**裁定**：验收不得以「代码里写了」充当证据。每条裁定须能给出**可观测断言 + 测试向量 + 预期**。
**写不出可观测断言的条目，说明该条本就没想清楚** —— 应退回补设计，而不是降低验收标准。
`src:` 用户级长期约定 · `00-index.md` X-05
