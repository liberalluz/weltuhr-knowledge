## 一、三项决策的定义

### SPEC-PLAN-001 源 = 材料 · 体系 = 顺序 · 方法 = 动作 + 判据
**裁定**：三段各管一件事，**互不替代**。

| 段 | 管的 | 换个说法 | 例子 |
|---|---|---|---|
| **源** | 知识从哪来 | 换材料不改顺序 | L1 官方文档 / L2 教材 / PEP / CEFR |
| **体系** | 先学哪个 | 换顺序不改动作 | Tutorial 序 / 语法分层 / 工程路线 |
| **方法** | 每一项具体怎么学 + 怎么算学会 | 方法一换，完成判据也换 | 费曼 / 间隔重复 / 刻意练习 / 跟读模仿 / 项目驱动 |

**判据**：换材料不改顺序，换顺序不改动作。
`src:` 第 45 轮（已定口径）

### SPEC-PLAN-002 方法同时决定「怎么算学会」
**裁定**：方法不只决定动作，还决定完成判据：费曼 = 「能讲清」，间隔重复 = 「到期还能想起」，刻意练习 = 「弱项达标」。所以**方法一换，`mastery` 里「已掌握」的含义也跟着变**。
`src:` 第 45 轮

### SPEC-PLAN-003 三项挂在 `Plan` 上，不是空间属性
**裁定**：源 / 体系 / 方法是**空间级**的，但属于 `Plan` 而不属于空间本身。换一套源或体系，`⪯`、六要件、内容包一个字都不改、一次都不用重新下载 —— 只是同一批内容换一种走法。
**因此同一空间可并存多份 `Plan`**（如「入门跑通」与「专攻异步」），各自配不同的源 / 体系 / 方法。
`src:` 第 39 轮

### SPEC-PLAN-004 三级分工，互不可替代
**裁定**：

```
spaceId  → 边界（内容包决定）
target   → 范围（随视距：Z1≈150 / Z3≈12 / Z4=1）
源/体系/方法 → 怎么做（Plan 决定）
```

**想只学语法域，用的是收窄 `target`，不是给语法域另配一套体系。**
`src:` 第 39 轮 · FND-006

### SPEC-PLAN-005 域不能单独选体系
**裁定**：体系是 `⪯` 的排序依据，而 `⪯` 在空间内唯一。给每个域各选一套体系，等于要求空间内存在多套排序，与「独立 `⪯`」判据直接冲突。域只能被 `target` 圈定，**不能带自己的规划**。
`src:` 第 39 轮

## 二、三处出处

### SPEC-PLAN-006 三段候选各有三处出处
**裁定**：源、体系、方法**结构相同**，各有三处出处：

| 出处 | 谁写 | 作用 |
|---|---|---|
| **平台内置** | 产品方 | 与内容无关的通用档，保底 |
| **空间包默认** | pack 作者 | 随包下发，「这个空间该用什么」的作者答案 |
| **用户 / 社区自建** | 学习者或社区 | 本地 overlay，或过审后进公共 overlay |

**一条线不能有自建、另一条没有** —— 三者对称。
`src:` 第 42–44 轮

### SPEC-PLAN-007 「+ 自建」是三段列表尾部的一个动作
**裁定**：自建**不是独立功能或独立页面**，而是每段候选列表尾部的「+ 自建」。链路完全一样：

```
草稿（本机） → 立刻可选但仅自己可见 → 提审（GOV 四裁定） → 合并进 overlay 后他人可见
```

**不做「我的方法库」这类独立页面** —— 那等于把「建」和「选」拆成两处，用户建完还得回来选。
`src:` 第 44 轮

### SPEC-PLAN-008 三段候选卡形态一致
**裁定**：每张卡的元素相同：**名字 · 出处标签 · 适用范围 · 版本 · 尾部「+ 自建」**。用户在第三段看到的东西与第一、二段长得一样，不需要重新学一遍。
`src:` 第 44 轮

### SPEC-PLAN-009 方法不标权威等级
**裁定**：源有 L0–L4、体系有 L 层标级，但**方法没有权威谱系** —— CEFR 是标准、PEP 是官方文档，而「费曼学习法」没有等级可标。**给方法编一个权威等级，等于把「谁说的」当成「对不对」。**
**替代做法**：标「适用依据与出处」，并把可信度差异放到**进度**上（`verified / checked`，见 QUANT）。
`src:` N-k

## 三、方法的两条边界

### SPEC-PLAN-010 方法的适用粒度：空间级选 + 按类型派生
**裁定**：用户在 ③ 选**一套** profile，具体到每一项时按 `Item.type` 自动派生（陈述题走费曼、程序题走刻意练习、语音题跟读）。
**不做项级覆盖**（不做 `perItemMethodOverride`）：表达力更强，但会变成「150 项 = 150 次选择」。
`src:` N-h

### SPEC-PLAN-011 方法可自建，但只能自定「配方」
**裁定**：

| 可自定 | 不可自定 |
|---|---|
| 步骤数 · 先后 · 循环 | **执行算子**（6 类之外不得新增） |
| 每步判据与参数 | 事件类型与日志结构 |
| `phase`（可覆盖派生值） | SRS 时钟 |
| 是否有 `hint` | 进度 / 掌握度的计算口径 |

**理由**：算子是可执行、可记日志、可纳入进度的最小单位。允许自创步骤语义 = 造一个引擎无法识别的动作，「零代码接入」当场失效。
`src:` 第 42–43 轮 · `not-list.md` §三

## 四、体系逆序

### SPEC-PLAN-012 逆序不禁止，但必须算清并显示
**裁定**：体系候选不满足 `⪯`（如工程路线先教框架再教装饰器）时：

- **不删候选**（「我想先上手做项目」是真实需求）
- **算逆序数**（`inversions`），在卡上显式写「本序 4 处逆序，第 3 步会卡在装饰器」

**判据**：让代价可见，而不是替用户否决。
`src:` N-j

### SPEC-PLAN-013 排序不等于降权，更不等于折叠
**裁定**：体系按逆序数升序排列时，「工程路线」会沉到末尾 —— 但它**必须仍在列表里完整可见**。实施者若为「列表干净」把它折叠或置灰，就等于把「不禁止」改成了硬禁，**性质完全变了**。
`src:` Z-SORT 连带

## 五、Planner 界面

### SPEC-PLAN-014 单页三段 + 右侧实时预览
**裁定**：左栏四段竖排（源 → 体系 → 方法 → 确认），右栏实时预览；iOS 改三步分页。
**顺序固定不可打乱**，因为三步之间有真实依赖：源决定体系候选（圈外不得进候选）→ 体系决定步骤顺序 → 方法决定每步形态。**所以不能做成三栏并列。**
`src:` N-i

### SPEC-PLAN-015 实时预览只显示三项
**裁定**：**项数 · 分母 · 预计时长**。

- **分母 = 圈内项数**（含未纳入路径的游离项），不随体系覆盖度变化
- **时长** = Σ(算子系数 × 步骤数 × 项数)，系数见 `C-14…C-19`
- **难度分布已删除** —— 建计划时 `D` 尚不存在（FSRS 首次评分才初始化），而 `φ` 不能当难度代理

**预览会随三段选择逐步精细化**：选完 ①② 时还没有方法，只能按平台内置默认 profile 估算，选完 ③ 再重算。
`src:` V-2 · V-7

### SPEC-PLAN-016 三个入口指向同一面板
**裁定**：

| 入口 | 在哪 | 带什么进去 |
|---|---|---|
| Z1 星系「开始学习」 | ③ 区右侧，**仅在空间内出现** | `spaceId`，`target` 默认全量 |
| 进展视图「新建计划」 | 进展视图含空状态 | 空（先选空间） |
| 定位结果「按此范围建计划」 | ④ 每行或底部 CTA | **自动带入 `target`**，不重选空间 |

第三条最关键：搜到「Python 异步」后用户要的是**为这个范围建计划**，不是再走一遍「选空间 → 选体系」。
`src:` 第 40 轮

### SPEC-PLAN-017 Planner 不是视图
**裁定**：Planner 是**一套流程**，不是第六个视图。它不常驻、不占 HUD 位置、不出现在 ⑤⑥ 附近 —— 它是「对某个空间跑一次规划」，做完就进 Runner。
`src:` 第 40 轮

### SPEC-PLAN-018 详情页不给规划入口
**裁定**：详情是**项级事实**，规划不属于它。详情里只**只读显示**「所属体系」，点它是跳到 Planner ② 段，属回链而非入口。
`src:` 第 40 轮

### SPEC-PLAN-019 重入复用同一面板
**裁定**：Runner 暴露缺口后回 Planner 时，**预填上次取值、`Plan.version + 1`**，不新开「重规划界面」。这是「Planner ↔ Runner 交替循环」的直接结果。
`src:` N-5 · 第 40 轮

## 六、候选排序与推荐

### SPEC-PLAN-020 三段各用各的排序键
**裁定**：

| 段 | 排序键 |
|---|---|
| 源 | 出处等级（L0 > L1 > L2 > L4） |
| 体系 | 逆序数从少到多 |
| 方法 | `Item.type` 覆盖率（由 `appliesTo` 算出，**不需新增字段**） |

**三者的好坏标准本就不同**，强行统一等于用一个键衡量三种东西（方法无权威谱系，强给 L 级就是编的）。
`src:` Z-SORT

### SPEC-PLAN-021 推荐是做排序与给理由，不是一键生成
**裁定**：拆两级，只做 A：

| 级 | 内容 | 处置 |
|---|---|---|
| **A 排序 + 理由** | 候选仍是你自己选，但按上述键排序并显示「为何推荐」 | ✅ 做 |
| **B 一键生成 Plan** | 跳过三段，系统直接定 | ❌ **不做**，见 `not-list.md` N-04 |

**A 该做的理由**：L 级与逆序数**本来就在候选卡上显示**，只是一直没拿来排序 —— 不需要新增字段。
`src:` Z-RE
