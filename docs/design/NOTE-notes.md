# NOTE · 笔记

> **前置阅读**：[FND](FND-foundation.md) · [PACK](PACK-content-pack.md) · [STEP](STEP-learning-steps.md)。
> **明确不管**：笔记模板的具体排版（平台层声明，随产品版本演进）· 笔记内容的正确性（内容作者）· 笔记进不进量化（**不进**，见 [QUANT-001](QUANT-quantification.md)）。

## 一、定位

### SPEC-NOTE-001 笔记是派生产物，不是第四种「源 / 体系 / 方法」
**裁定**：笔记由「**体系 + 六要件**」渲染得出，是**产物**而非决策项。

| 已有三项 | 管什么 | 笔记是否同类 |
|---|---|---|
| 源 | 出处 | ❌ 笔记不提供出处 |
| 体系 | 顺序 | ❌ 笔记**由**体系派生 |
| 方法 | 动作 + 判据 | ❌ 笔记是产物，不是动作 |

**这条定位直接决定三件事**：它该不该进包（不）、进不进量化（不）、需不需要自己的同步机制（不需要，复用事件流）。
`src:` 第 58 轮

### SPEC-NOTE-002 生成从 `Scheme` 派生，不从 `⪯` 派生
**裁定**：`⪯` 是偏序，笔记是**线性章节序列**。已定「体系 = `⪯` 的线性扩展」，因此笔记骨架天然等于体系序列，**不需要另设一套顺序**。
`src:` 第 58 轮约束 1

### SPEC-NOTE-003 笔记不进量化
**裁定**：笔记的任何层（生成 / 自动补 / 手写）**都不进 `d`**。`d` 只看六要件。
**否则**改笔记能改掌握度 = **第二个刷分后门**，与已封顶的打卡同族（见 `not-list.md` N-14）。
`src:` 第 58 轮约束 3

### SPEC-NOTE-004 章节树是投影，不是数据
**裁定**：章节顺序由 `Scheme` 渲时投影得出，**不落库**。`Scheme` 本就属于 `Plan`，所以章节顺序天然是 **Plan 级视图**。

```
宇宙     = r/θ/φ 的投影
树视图   = ⪯ 的投影
笔记目录 = Scheme 的投影        ← 同一范式
```

**这解释了「内容空间级 + 顺序 Plan 级」为什么能成立**：换 Plan 只重排章节，内容一字不丢。
`src:` X-D · 第 62 轮

## 二、两套笔记

### SPEC-NOTE-005 两套笔记必须共用 `itemId` 锚点
**裁定**：标准体系笔记与自建笔记**一律以 `itemId` 为锚**。
**这是「随时切换」成立的唯一前提** —— 若自建笔记不对应任何项，切换只能整篇替换，无法就地对照。
`src:` NB-5 · 第 58 轮约束 2

### SPEC-NOTE-006 空间级自由笔记
**裁定**：允许写「整个空间的学习感想」，`itemId` 为空，**不参与两套切换**（切换控件置灰）。
`src:` NB-5

### SPEC-NOTE-007 位置：详情页第四分区 + 修习侧栏
**裁定**：详情页现有「事实区 / 缺口区 / 信息区」之外加**笔记区**，两套切换就在这里（唯一有共同锚点的地方）；修习时以**侧栏**唤起（R3 已定全屏沉浸，侧栏是唯一合法外挂形态）。
**不新增视图**（见 `not-list.md` N-11）。
`src:` NB-4

## 三、三层内容

### SPEC-NOTE-008 每节有三层，三层都保留
**裁定**：

| 阶段 | 时机 | 谁写 | 层 |
|---|---|---|---|
| **t0 生成** | Planner ② 之后 | 系统按 `Scheme` 排章节 + 四要素占位 | `generated` |
| **t1 自动补** | 进入该项修习时 | 系统填该项**已有**六要件内容 | `autoFilled` |
| **t2 手动补** | 随时 | 用户 | `authored` |

**显示优先级 `authored > autoFilled > generated`，但三层都保留。**

**为什么必须保留三层**（这不是冗余）：包升级重渲染时，**只有靠它才分得清哪一段是用户写的**。
`src:` NB-3（用户改的口径）· 第 59 轮

### SPEC-NOTE-009 自动补不得覆盖已手改的节
**裁定**：t1 每次都幂等补齐**未填**的占位，**已 `authored` 的内容不动**。
**触发面**：④ 每次进入都补齐；**⑥ 保持不触发**（复习不需要笔记）。
`src:` X-E

### SPEC-NOTE-010 自动补不得来自模型
**裁定**：t1 只能把 pack 里**已有的**六要件内容机械展开。**不调模型**。
**理由**：M2a 离线闭环是硬约束；且模型生成内容与 pack 不同步、不可复现。
`src:` NB-9 · 第 59 轮

### SPEC-NOTE-011 三态落位：齐 / 缺 / 不可外化
**裁定**：

| 要件态 | 笔记里 |
|---|---|
| 齐 | 已填 |
| 缺 | 空位 + 标「待补」 |
| **不可外化** | **「需在实践中体会」**（独立一态） |

**「不可外化」与「待补」不得同形** —— 同形会引导用户去伪造默会知识，且用户会把「补不上」归因为自己不够努力。
`src:` X-F

### SPEC-NOTE-012 每节必须带来源标记
**裁定**：每个节要能看到它的内容是**生成 / 自动补 / 手写**。
**理由**：与「方法出处标签」「源 L 级标级」同族 —— **用户得知道自己看到的东西是谁给的**。缺了它，用户改完一段、包一升级又冒出一段旧的，会以为是自己记错了。
`src:` 第 59 轮连带

## 四、版本

### SPEC-NOTE-013 版本按节独立计数
**裁定**：`noteVersion` **按节**（`itemId + sectionKey`）自增，不是整本一个号。
**回滚** = 追加一条带 `targetVersion` 的 `note_revised` 事件，**不删历史**。

**为什么不能整本一个号**：改一个字整本 +1，重渲染时分不清哪些节真变了，「这一节改了什么」永远答不出来。
`src:` Z-版本

### SPEC-NOTE-014 版本不建表，由事件 fold
**裁定**：版本号 = 该节 `note_revised` 事件计数，`fold` 得出。
**「留不留版本」不是选择，而是「能不能跨设备用」的前提** —— 任何要跨设备同步的可写状态，其修改都必须是事件。
`src:` NB-1 · NB-8（降级为推论）

### SPEC-NOTE-015 包升级：生成层重渲染，编辑层叠加
**裁定**：与 overlay 同构 —— `generated` 随 `spaceVersion` 重渲染，`autoFilled` / `authored` 按 `itemId` 叠加。
**项被删** → 标「已下线」（见 NOTE-016）；**项被拆** → 笔记**全额复制**到各子项（文本不能打半份，见 [PACK-014](PACK-content-pack.md)）。
`src:` 第 58 轮 · X-B

### SPEC-NOTE-016 项下线后笔记挂能力清单「历史」区
**裁定**：`Z4` 已定孤儿项折叠到能力清单「历史」区，**笔记跟着它走**：在历史区点一项可看它的笔记（**只读 + 可导出**）。
**不新建「历史笔记」列表**（入口碎片化，且与历史区重复）。
**这条不能省**：项在包里已找不到、详情页进不去，若不处理，用户学过的东西会因为别人改了包结构而**在界面上彻底消失**。
`src:` Z-下线

## 五、导出

### SPEC-NOTE-017 单向快照，不做双向同步
**裁定**：只出不进。**双向等价于在 HLC 之外再造一条因果链**，两套定序语义并存时「哪边是真相」永远无解（见 `not-list.md` N-02）。
**代价要认**：导出后在 Obsidian 里学的，Weltuhr 不知道 —— 进度、SRS、掌握度都不跟随，产品只剩「调度官」这一个角色。
`src:` NB-2

### SPEC-NOTE-018 三段版本戳（取代原「双版本戳」）
**裁定**：每节独立计数后，**不再存在单一 `noteVersion`**。导出戳改为三段：

```
spaceVersion + noteDigest（笔记集合摘要） + 各节 front matter 自带 noteVersion
   包版本           整本可比对                  单节可回滚
```

原来的「双版本戳」其实藏了两个需求：**整本比对**（判断导出件是否过时）与**单节回滚**。拆成三段后两者都被满足。
`src:` Z-版本 连带

### SPEC-NOTE-019 格式与软件解耦
**裁定**：定的是**内部规范格式**（Markdown + front matter，含 `itemId` / `spaceVersion` / `noteVersion`），目标软件只是**适配器**。格式必须同时能表达**层级 · 锚点 · 双链** —— Markdown 目录树全占。
**目标软件清单与打包形态为 TBD**（见 `00-index.md` TBD-3 / TBD-4）。
`src:` 第 58 轮 · 第 63 轮
