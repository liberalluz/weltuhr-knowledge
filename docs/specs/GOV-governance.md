## 一、提交与审核

### SPEC-GOV-001 四种裁定
**裁定**：提交的裁定只有四种：

| 裁定 | 含义 |
|---|---|
| **通过** | 收进公共 overlay |
| **驳回** | 不收 |
| **合并到已有项** | 实为同义 ⇒ **收作别名**，不新建项 |
| **降为圈外成员** | 保留在圈外，不占圈内编号 |

**「合并到已有项」这一条不能缺**：用户 A 与 B 各建一个「装饰器」时必然得到两个 `Item.id`；没有合并出口，重复项只能驳回，用户提交时白费力气。合并后靠 `state_merged`（取较大 `S`）把两人的已学状态合到一起。
`src:` 早期治理裁定 · 第 76 轮

### SPEC-GOV-002 四件套是「审核通过」的必要条件，不是「提交」的门槛
**裁定**：**必须分开**：

```
用户提交：最小三字段（标题 / 所属域 / 一句描述）
    ↓
审核方补全或退回补全
    ↓
四件套齐备（归位 / 前提边 / 六要件 / L 层来源）才可能裁定「通过」
```

**不改清这句话，规格里会同时出现「缺一即拒收」和「只填三项」，实施者只能二选一并得罪另一条。**
`src:` DT-8 连带

### SPEC-GOV-003 最小三字段 + 标题预填
**裁定**：用户只填 **标题（用搜索词预填）· 所属域 · 一句描述**。六要件、六轴其余、前置声明**全部留给审核方**。
**判据**：用户已用「说出这个词」表达过一次，不该让他改填六个格；而审核方本来就要做归一化。
`src:` DT-8

### SPEC-GOV-004 首期只做项级新增
**裁定**：用户只能往**已有空间**补单个 `KnowledgeItem`。域级与空间级后置（空间级 = 一个新 pack，审核解决不了内容生产）。
`src:` DT-7

### SPEC-GOV-005 前置可以留空
**裁定**：新增「装饰器」需要前置「闭包」时，若闭包也不存在，**允许前置为空** —— 该项落进已定的「**游离项 · 未纳入路径**」分组，由审核时补边。
**好处**：不新增状态，且正好用上那个已有分组。
`src:` 第 76 轮

### SPEC-GOV-006 首期重复检测靠标题近似 + 人工裁定
**裁定**：原设计写「疑似重复检测（**aliases 命中**）」，但 **`Item.aliases` 首期不实现**（不扩 schema）。故首期降级为：**标题近似匹配 + 审核方裁定**。
**不写清这一点，首期实施会去实现一个不存在的字段。**
`src:` DT-3 · `not-list.md` N-08

### SPEC-GOV-007 提交即入本地 overlay
**裁定**：见 [PACK-011](PACK-content-pack.md)。治理侧的含义是：**审核是异步的，不得阻塞学习**。
`src:` DT-9

### SPEC-GOV-008 双平面治理：两条链路不同
**裁定**：

| 对象 | 链路 | 审核 |
|---|---|---|
| **个人自建**（源 / 体系 / 方法 / 笔记） | 本地 overlay | **不审核**，仅本人可见 |
| **社区共享** | 提交 → 四裁定 → 公共 overlay | 审核 |

方法只是多了一种被提交的对象，**不另开机制**。
`src:` 第 41–44 轮

### SPEC-GOV-009 审核粒度与内容层一致
**裁定**：审核的粒度 = `item` 级，与 D5 已定口径一致。四件套的检查在**审核侧**执行，不在提交侧。
`src:` DT-7

## 二、跨设备合并

### SPEC-GOV-010 全序来自 HLC，不用服务端序号
**裁定**：见 [FND-011](FND-foundation.md)。治理侧的关键判据：**离线也要能写事件** ⇒ 服务端递增序号不可用；**FSRS 的 `D`/`S` 不可交换** ⇒ 只有偏序不够。
`src:` Z1

### SPEC-GOV-011 同一项被两台设备都学了一遍：不去重
**裁定**：两个事件序列**都重放**。
**这不是 bug**：你确实复习了两次，`S` 就该变长；去重反而违背复习语义。
**去重只针对「同一条事件被上传两次」**，靠 `id` UNIQUE 索引（见 `event-types.md` §一）。
`src:` Z2

### SPEC-GOV-012 迁移事件化 = 事件溯源不出现破口
**裁定**：见 [PACK-013](PACK-content-pack.md)。治理侧补一条：`state_carried` / `state_merged` / `item_retired` 三种事件须进**审计视图**，可回答「这个项到底是什么时候、被哪次包升级改的」。
`src:` Z3

### SPEC-GOV-013 孤儿项：事件全留 + 标已下线 + 历史区
**裁定**：见 [PACK-016](PACK-content-pack.md)。治理侧的判据是**两个「不可逆」必须并存**：
- 已学不可撤销（QUANT-003）
- 项可下线（否则包里永远删不掉东西）

**让两者并存的唯一做法**：状态留在事件流里，项的可达性降到「历史」区。
`src:` Z4

## 三、降级与容错

### SPEC-GOV-014 降级五档全可用
**裁定**：帧率不足 / 无障碍需求 / 用户手动切换时进入降级态，但 **Z0–Z4 五档全部可用**；切换器只剩 `树 / 链 / 详情`，宇宙段置灰并**显示一行原因**。
**判据**：降级只降**渲染方式**，不降**功能可达性**。
`src:` 第 33 轮 · VIEW-023
