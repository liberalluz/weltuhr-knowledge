# 骨架数据规格

> **本文件是骨架数据集的唯一权威处**：三轴用哪份目录、各层取什么条目、节点如何编号与定位、体积预算。
> 其余文档一律引用不复制。包的装载与 manifest 字段见 [`entity-fields.md`](entity-fields.md) §1；path 的 16 条规则见 [`path-rules.md`](path-rules.md)（`2026-10-20` 成文 —— 此前四份文档都写「见插件标准」，而该文档不存在），本文件不复述。
> 定位：`B13b` 的输入规格。**本文件定稿后 `B13b` 才可开工**（`SDP` §4.2）。`B13a`（实体层）不依赖本文件 —— 这也是 `B13` 拆两半的理由。

## 一、什么是骨架

骨架 = **根 → 恒星槽位**，全量内置、不走插件、不进审核（`ADR-0005` 决策 2）。恒星槽位是**骨架与载荷的分界线**：恒星以下（行星系 / 行星）由载荷包提供。

因此骨架只需满足一个条件：**给出足够细的、有法定依据的挂载点**。它不承载可学项，也不承载学习内容。

## 二、三轴数据源（唯一权威）

| 轴 | 目录 | 版本 | 层级与数量 |
|---|---|---|---|
| 学科 | 研究生教育学科专业目录 | **2022** | 门类 14 · 一级学科 117 · 专业学位类别 67（博士 36 + 硕士 31） |
| 专业 | 普通高等学校本科专业目录 | **2025** | 门类 12 · 专业类 93 · 专业 845 |
| 角色 | 中华人民共和国职业分类大典 | **2022** | 大类 8 · 中类 79 · 小类 449 · 细类 1,636 |

**三条纪律**：

1. **只用上表这三份文件，不拼接其他分类标准。** 特别地：不得引入 GB/T 13745《学科分类与代码》补充学科轴 —— 它的 62 个一级学科与研究生目录的 117 个一级学科不同源，混用会产生无法挂接的孤儿。
2. **目录版本即骨架版本。** 目录年度更新（本科专业目录已确立年度更新机制）时，骨架走**增量**：新增节点加、撤销节点标墓碑（`PathClaim`），**不得整体重建** —— 整体重建会让 `id` 漂移，用户进度随之失联。
3. **官方码优先。** 每层条目若带官方代码，一律入库为 `official_code`；它是 `id` 的组成部分（见 §四）。

## 三、槽位映射

八槽位中，三轴**实际占用的槽位不同**（`entity-fields.md` §2 已明令禁止用绝对层号）：

| 槽位 | 学科轴 | 专业轴 | 角色轴 |
|---|---|---|---|
| `supercluster` 超星系团 | **轴根 1** | **轴根 1** | **轴根 1** |
| `group` 星系群 | 门类 14 | 门类 12 | 大类 8 |
| `galaxy` 星系 | — | 专业类 93 | 中类 79 |
| `cluster` 星团 | — | — | 小类 449 |
| `star` **恒星** | **一级学科 117 + 专业学位类别 67 = 184** | 专业 845 | 细类 1,636 |
| `system` / `planet` | 载荷 | 载荷 | 载荷 |

### 学科轴为什么只有两个内容层

研究生目录**只到一级学科**：二级学科由学位授予单位自主设置，**不存在全国统一目录**。所以学科轴在 `group`（门类）之后只能直接到 `star`（一级学科 + 专业学位类别），跳过 `galaxy` 与 `cluster`。

两个直接后果，都是**已知并接受**的：

| 后果 | 处置 |
|---|---|
| 一个门类下直接挂 8–50 颗恒星，视觉上「星系群里没有星系」 | 宇宙侧按门类把恒星**聚簇**分布（点云密度表达星系感），不造中间层。这是 `B17b` 的渲染约定，不是数据结构 |
| 一级学科粒度偏粗（如 0812「计算机科学与技术」覆盖整个领域） | 由载荷包的子树补偿 —— 决策 2 允许载荷带「恒星 → 行星系 → 行星」两级，包内再分方向 |

> **不得为凑视觉对称而补造第三层。** `ADR-0005` 决策 1 的判据是「容器轴须有官方法定分级编目 + 唯一父级」，编目到哪一层，骨架就到哪一层。深度是编目的函数，不是设计参数。

### 一条被移除的旧数据

`entity-fields.md` 旧版把学科轴 `star` 层写作「二级 / 方向 **676**」。该数字**无法溯源**：

- 676 恰好等于 GB/T 13745-2009 的**二级学科总数**（该标准 5 门类 / 62 一级 / 676 二级）
- 但 GB/T 13745 的 62 个一级 ≠ 研究生目录的 117 个一级，676 个二级挂不到 117 个一级下
- 即 `14 → 117 → 676` 这条链在**任何单一数据源里都不成立**

故移除。连带：骨架总数由 **3,929 → 3,323**。

## 四、编号与定位

| 项 | 规则 |
|---|---|
| `id` | `<axis>/<official_code>`；无官方码时用 `<axis>/<slug>`。骨架层一律有官方码 ⇒ **骨架 id 全部由码构成** |
| `axis` | `discipline` / `major` / `role` —— 三个轴根即 `/discipline`、`/major`、`/role`，同时消解 path 冲突 |
| `path` | 位置，由父级 `path` + 本段 slug 拼成；同父唯一；slug 为 kebab-case。16 条规则见 [`path-rules.md`](path-rules.md)，本文件不复述 |
| `URI` | = `path` |
| `official_code` | 官方代码原样存储（含前导零，如 `0812`）；**不得转成数字** |
| `level_slot` | 取 §三 表；**存槽位名，不存层号** |
| `depth` | 派生 = `level_slot` 在轴内的序号，仅供展示，**不得用于判据** |

**为什么 id 用官方码而不是 slug**：官方码是法定标识，**改名不改码**。专业目录 2025 就发生过条目更名；若 id 建在名称上，更名即等于删旧建新，用户进度全部失联。这条与 `ADR-0005` 决策 7「身份与地址分离」同源。

## 五、节点数与体积

| 轴 | 构成 | 节点数 |
|---|---|---|
| 学科 | 1（轴根）+ 14 + 117 + 67 | **199** |
| 专业 | 1（轴根）+ 12 + 93 + 845 | **951** |
| 角色 | 1（轴根）+ 8 + 79 + 449 + 1,636 | **2,173** |
| **合计** | | **3,323** |

**与旧值 3,929 的差额**：`−676`（移除无源的二级学科层）`+67`（补入专业学位类别）`+3`（旧表未计三个轴根）= **−606**。

**体积口径**（必须写明，否则「数百 KB」与实测对不上）：

| 口径 | 估算 |
|---|---|
| 单节点最小集（`id` / `path` / `name` / `axis` / `level_slot` / `official_code` / `main_parent_id`） | ≈ 300 B |
| 未压缩 JSON | **≈ 1.0 MB** |
| 压缩后（包内 brotli） | **≈ 220–300 KB** |

⇒ `ADR-0005` 决策 2 的「数百 KB」指**压缩后**。天球贴图**不进骨架包**（`ADR-0006` 决策 4），否则预算直接崩。

## 六、产出步骤（一次性数据工程）

`B13b` 开工前完成，产物落 `content/skeleton/`（源数据入库），构建产出 `skeleton` 包（不入库）。

| # | 步骤 | 完成判据 |
|---|---|---|
| 1 | 取三份目录的官方电子版（PDF / Excel / 官方公示页） | 三份均带版本号与发布日期，来源可回溯 |
| 2 | 转结构化 JSON（脚本抽取 + 人工逐条校名） | 条目数与 §五 表**逐轴相等**；差异须逐条说明 |
| 3 | 生成 `id` / `path` / `level_slot` / `official_code` | `id` 全局唯一；`path` 同父唯一；三轴根各一个 |
| 4 | 机器校验 | ① `official_code` 在轴内唯一 ② 主父唯一 ③ 无环 ④ 无孤儿 ⑤ 每个 `star` 的父链完整到轴根 |
| 5 | 体积核算 | 压缩后 ≤ 300 KB；超出须说明 |
| 6 | 快照登记 | 三份目录的版本与条数写入 `SCMP` 基线，作为**增量比对的基准** |

> 步骤 2 的人工校名不可省：目录 PDF 的抽取结果在**全角/半角括号、连接符、异体字**上必然有偏差，而这些字符会直接进 `slug` 与 `path`。抽查发现一处即整表复验。

### 步骤 1 的来源与取得状态（`2026-10-20` 核）

| 轴 | 官方出处 | 文号 / 日期 | 载体 | 取得方式 |
|---|---|---|---|---|
| 学科 | 教育部《研究生教育学科专业目录（2022 年）》 | 学位〔2022〕15 号 · 2022-09-13 | PDF（`moe.gov.cn` 直链） | ✅ 可直接下载 |
| 专业 | 教育部《普通高等学校本科专业目录（2025 年）》 | 教高函〔2025〕3 号 · 2025-04-01 | PDF（`moe.gov.cn` 直链） | ✅ 可直接下载 |
| 角色 | 人社部《中华人民共和国职业分类大典（2022 年版）》 | — | **在线查询系统（无导出）** | ⚠️ **待拍板** |

> ⚠️ **角色轴是唯一没有电子档的一份。** 官方只有「技能人才评价工作网 · 职业分类系统」在线逐级浏览（可「全部展开」，列 编码 / 名称 / 工种数量），**不提供 Excel / JSON 导出**；另有纸质版发行。三条路各有代价，`B13b` 开工前必须拍其中一条：
> **(A) 按在线系统逐级抓取** —— 能拿全量，代价是要写抓取脚本 + 逐条人工校名（步骤 2 那条纪律照旧）；**未核**：该系统覆盖范围是否等于 §五 的 1,636 个细类。
> **(B) 采购纸质书自行录入** —— 最权威、最慢，且仍是人工。
> **(C) 角色轴只到 `cluster`（小类 449，砍掉 1,636 个细类）** —— 骨架总数 3,323 → **1,687**，角色轴在 §五 的占比由 65% 掉到 32%。这是**改口径**，须走 ADR 级裁定，不得在 `B13b` 里自行降级。
>
> **已裁（`2026-10-20`）：取 `(A)`。** 判据：`(A)` / `(B)` 都不改口径、只影响工期；`(C)` 改口径 —— 角色轴降到小类后，挂载点会粗到与学科轴同类（学科轴只有两个内容层已是已知妥协），载荷包要补的层级更多，而它省的只是 1,636 条录入。`(A)` 与「官方目录为唯一权威」不冲突：内容仍出自官方系统，变的只是取得手段（从「下 PDF」变成「抓官方页面」）。
> **执行前还有两件事**：① **核覆盖范围** —— 该系统是否恰好覆盖 §五 的 1,636 个细类；不等则须逐轴说明差异（同步骤 2 的判据：差异须逐条说明，不得默默少几条）。② **抓取脚本落 `content/tools/`**，产物与 PDF 抽取同规：原样落 `content/skeleton/` 源层，结构化在步骤 2 做 —— **不得边抓边转**，否则「条目数对不上」时无从判断是漏抓还是抽错。
