## 一、七步总览

### SPEC-STEP-001 七步是「3 + 4」，不是七个页面
**裁定**：

| 段 | 步 | 频率 |
|---|---|---|
| **建计划** | ① 选源 · ② 选体系 · ③ 选方法 | **跑一次**（每个 Plan） |
| **执行** | ④ 修习 · ⑤ 检验 · ⑥ 保持 · ⑦ 出口 | **每项跑一遍**（⑦ 是状态转换，非每项动作） |

七步是**进度分段**，不是七个界面。①②③ 同属 Planner（见 PLAN）；④⑤⑥ 共用一个 Runner；⑦ 是事件而非步骤。
`src:` 第 46 轮 · X1

### SPEC-STEP-002 三层状态单调递进
**裁定**：**未学 → 已学 → 毕业**，三层全部**不可逆**。

| 状态 | 判据 |
|---|---|
| 已学 | ⑤ 首次验收合格（判据为空时 = 步骤跑完） |
| 毕业 | `S ≥ 180` 天 |

复习未过**不撤销已学**，只降 `S`、提前 `due`、降掌握度，**进度分母不动**。
`src:` QUANT M4 · X2

## 二、④ 修习：一个 Runner

### SPEC-STEP-003 一个 Runner + 三条入队源
**裁定**：④ 修习与 ⑥ 保持**动作完全相同**（都是按 `methodProfile` 展开某项的步骤序列并执行），唯一区别是**为什么现在学它**。故合并为**一个执行器 + 三条入队源**：

| 入队源 | 触发 | 排序依据 |
|---|---|---|
| 体系序（新学） | 按 `Scheme` 走到下一项 | 只看 `⪯` 前沿 |
| SRS 到期（保持） | 到了 `due` | 到期时间 |
| 缺口回补（检验） | ⑤ 判为「前置缺」 | 缺口位置，优先补前置 |

**不做两个界面**：拆开会让用户每天先判断该点哪个入口，且同一项的步骤序列要写两遍。
`src:` R1

### SPEC-STEP-004 队列排序规则
**裁定**：**逾期天数降序 → 复习池 → 新学池**，两池独立计数（`C-06` / `C-07`）。
`src:` S3 连带

### SPEC-STEP-005 会话边界：时间预算 + 项边界收尾
**裁定**：默认预算 25 分钟（`C-05`）。**到点不切断进行中的项**，等该项的步骤序列走完、到下个项边界（= **⑤ 检验完成之后**）才收尾。

**为什么不按项数**：项粒度差两个数量级（单词 30 秒 / 异步范式 40 分钟）。
**为什么不纯时间盒**：切断会留半成品 —— 既不能算完成也不能算未学，掌握度无处记账，进度分母漂移。
`src:` R2 · EX-4

### SPEC-STEP-006 会话产出 = 已完成项 + 跳过项
**裁定**：每次会话产出「**已完成项集合 + 跳过项集合**」，两个集合都是整数个项，可干净进入 ⑥ 的 `due` 排期。
`src:` R2 · SF-2

### SPEC-STEP-007 会话内不改变 `⪯` 可及性
**裁定**：修习中**不能跳着学**。要跳只能回树里换 `target`。
`src:` R1 连带

### SPEC-STEP-008 外壳：全屏沉浸 + 一条细位置条
**裁定**：隐藏宇宙与 HUD 六区块，只留顶部一条**细位置条**（当前项在路径的哪一段 / 本会话还剩几项 / 退出）。
**这条细条是 ① 面包屑的降级形态，不新增概念。** 修习态与浏览态是两个 `mode`；切回宇宙时 `cameraState` 保留。
`src:` R3

### SPEC-STEP-009 断点恢复：步骤级游标，由事件 fold
**裁定**：游标记 `(itemId, stepIndex)`，**从 `step_completed` 事件 fold 得出**，不建 `SessionCursor` 表。
fold 规则：`max(已完成 stepIndex) + 1`。
**收益（比「不冲突」更实际）**：事件流本身 append-only，两台设备各写各的步骤事件，fold 出来就是同一条游标 —— 跨设备合并免费获得。
`src:` R4

### SPEC-STEP-010 一屏只显当前步骤
**裁定**：顶部细位置条 + 项标题常驻 + **当前步骤指令** + 操作区；步骤序列**不展开**，只显示「第 2/5 步」。
`src:` EX-2

### SPEC-STEP-011 手动推进 + 可回退
**裁定**：每步完成后用户点「下一步」，**可回退到上一步**。**回退不写事件** —— `step_completed` 不撤销，回退是纯视图操作（只是重看）。

**为什么不能自动推进**：「读完了」与「练够了」没有系统可观测的终点，自动推进必然判错。
`src:` EX-3

### SPEC-STEP-012 六类执行算子
**裁定**：`MethodProfile.steps[].operator` 只能取这 6 类之一：

| 算子 | 含义 | 界面形态 |
|---|---|---|
| **读** | 输入（读文本 / 看文档） | 滚动文本 + 「读完了」 |
| **例** | 看范本 | 范本对照 + 标注 |
| **忆** | 无提示复现 | 空白输入 + 「想不起来」 |
| **练** | 有反馈的产出 | 输入区 + 即时反馈 |
| **讲** | 向他人解释 | 录音或写作 + 自评清单 |
| **做** | 真实任务 | 任务清单 + 产物上传 |

**这是从已定六个方法反推得出的，不是另起一套。** 6 类与界面组件 **1:1**。
`src:` EX-1

> **命名已裁（`2026-10-20`，原 `OD-03`）**：⑤⑥ 的**标识符保持** `explain` / `do`，上表即终稿。`teach` / `build` 案被否 —— `build` 与 `content/tools/build.py`、`build/` 目录、CI 的 `build` 步骤**同词异义**，改了会让 `grep` 与日志在「打包」与「学习动作」之间分不清，且它与 ⑦「做出一个东西」的表述重叠。嫌 `do` 太泛，应在**中文名与说明**里写清（「真实任务，产出可提交的产物」），而不是改标识符。

### SPEC-STEP-013 定位算子 ≠ 执行算子（必须分清）
**裁定**：方法论文档 §6 的**五族 17 个是定位算子**（找到知识在哪，引擎执行）；本文件的 **6 类是执行算子**（对一项做学习动作，人执行）。
「算子必须在册」这句话没错，**错在指错了册** —— 五族 17 个里没有一个能当「讲一遍」「跟读」「默写」。
`src:` 第 65 轮纠错 · glossary §二②

### SPEC-STEP-014 `phase` 由算子派生
**裁定**：默认 读 / 例 → `first`；忆 / 练 / 讲 / 做 → `both`。作者可覆盖。
**连带**：「至少有一个 `review` 步骤」的校验等价于「至少有一个 both 类算子」。
`src:` EX-3 连带 · S2

### SPEC-STEP-015 ⑤ 自动进入，不给「稍后」
**裁定**：最后一步走完**即进 ⑤**，不需要用户点。
**理由**：检验是项的固有组成部分；给「稍后检验」就等于给了一条合法逃避通道（而跳过要移出会话，会拖死进度）。
**空判据分支**：判据为空（打卡式）时**跳过 ⑤**，直接记 `checked`。
`src:` EX-4 · V-6

### SPEC-STEP-016 Runner 入口：今日概览页
**裁定**：进 ④ 先看到**今日概览页**：复习 N 项 / 新学 M 项 / 今日预计时长 + 一个「开始」。开始后按队列排序统一执行。
**概览页是空间级的**（见 VIEW-022）；只有一个空间有活时不显示跨空间空壳。
`src:` V-3

## 三、⑤ 检验

### SPEC-STEP-017 判据分两层
**裁定**：

| 层 | 何时 | 写判定？ |
|---|---|---|
| **步内自检**（形成性） | 每个步骤内 | ❌ **不写** |
| **项末验收**（终结性） | 项末 | ✅ **唯一写入点** |

不拆开，掌握度会被「每步记一次」污染。
`src:` 第 48 轮

### SPEC-STEP-018 三档刻度
**裁定**：**未过 / 合格 / 熟练**。三档直接映射 FSRS：熟练 → 升档 · 合格 → 保持 · 未过 → 降档或重置并 `fail+1`（`C-04`）。
**不采用 0–5 六档**（用户无法自洽打分，实际会退化成「都打 4」，比三档更粗）。
`src:` E1

### SPEC-STEP-019 谁判：按判据类型派生
**裁定**：可自动判的（选择 / 填空 / 代码跑通 / 发音比对）**系统判**；不可自动判的（讲给别人 / 复述 / 默写）**自评 + 可选留证**。
`progressKind`（`verified` / `checked`）由判据类型**自动派生**，不需要用户标注。
`src:` E2

### SPEC-STEP-020 题目来源：pack 题库为主
**裁定**：**pack 内声明式题库**为主（离线可用、可复现、两次成绩可比）；模型生成只作**在线增强**，且**不参与 SRS 判定**（不计分）。
`src:` E3

### SPEC-STEP-021 不合格的两条出口
**裁定**：

| 类 | 判据 | 出口 |
|---|---|---|
| **没学会** | 连续未过 **< 2** 次 | 重跑该项 |
| **前置缺** | 连续未过 **≥ 2** 次（`C-09`） | 生成缺口，回 ④ 队列（缺口回补） |

**「连续」定义在事件序列上，中间出现一次「合格」即清零** —— 跨会话天然成立，不引入时间窗。
`src:` E4 · V-4

### SPEC-STEP-022 脚手架影响：封顶合格
**裁定**：**无脚手架才可判熟练**；用了提示或看过答案，**最高判「合格」**（`C-26`），`熟练` 档关闭。

**为什么不能「用了提示就判未过」**：那等于禁止使用提示，会把「对着答案能做对」与「完全不会」都映射成 `Again`，**`D`（难度）被错误拉高**，此后该项间隔永久偏短。
`src:` SF-1

### SPEC-STEP-023 检测边界：只约束可观测 + 明确不承诺防作弊
**裁定**：系统只约束它**观测得到**的（点看答案、离开题目页）；看不见的（翻书、问人）靠自报留痕。规格**明写「不承诺防作弊」**。
`src:` SF-3 · `not-list.md` N-10

### SPEC-STEP-024 跳过：移出本次会话，不写事件
**裁定**：跳过 = 「本次不想做」，不是「不会」。故：**不写判定事件**、不计 `fail`、不计已学、不回队尾，留到下次会话。
**连续 3 次跳过（`C-10`）** ⇒ 会话结束时提示「这一项可能前置不足，建议回 Planner」，**不硬判缺口**（弱信号，不生成用户不认可的缺口）。
`src:` SF-2 · SF-4

## 四、⑥ 保持

### SPEC-STEP-025 间隔算法：FSRS（三档映射）
**裁定**：用 D/S 双参数算法，三档直接映射 Again / Good / Easy。默认参数开箱可用（不必等个人数据拟合），两浮点本地可算，离线无依赖。
**SM-2 已被排除**：它需要 0–5 的 `quality`，而 E1 已定三档，三档无法还原六档。
`src:` S1

### SPEC-STEP-026 复习 ≠ 重学
**裁定**：每步带 `phase: first | review | both`，复习**只跑 `review`（含 `both`）的步骤**，不重跑「读定义 → 看例子」。
**否则**复习耗时约等于初学，每日配额第三天就爆表。
`src:` S2

### SPEC-STEP-027 自建方法必须校验「至少一个 review 步骤」
**裁定**：全部步骤都标 `first` 的 profile，由它完成的项**永远进不了 ⑥**。这是 `MethodProfile` 的**新增校验规则**。
**性质**：防「静默地绕过遗忘曲线」（而非防造假 —— 那条是「算子必须在册」）。
`src:` S2 连带

### SPEC-STEP-028 每日配额：两池软上限
**裁定**：复习池 20 / 新学池 5（`C-06` / `C-07`），**逾期最久优先**；今天没排上的**顺延到明天，不标欠账、不扣掌握度**。
`src:` S3

### SPEC-STEP-029 遗忘回退交给算法
**裁定**：不另立档位表。未过就是 `Again`，`S` 被压到极低、`D` 上升，回退由算法自然产生。
`src:` S4

### SPEC-STEP-030 逾期不是欠账
**裁定**：进度视图**不得**把逾期渲染成红色警示或「你欠了 N 项」。脉动只表达「到期待复习」，不表达「你欠了债」。
`src:` S3 连带

## 五、⑦ 出口

### SPEC-STEP-031 毕业是状态转换，不是步骤
**裁定**：⑦ 不是「每项末尾的应用练习步骤」。**「做出一个东西」属于 ④ 的一个步骤**（算子「做」）；⑦ 判定的是「这一项已经不靠学习材料了」。
`src:` X1

### SPEC-STEP-032 毕业判据：`S ≥ 180` 天
**裁定**：`S` 跨过半年量级，物理意义是「半年不复习仍大概率想得起来」—— 这正是「脱离学习材料还能用」的可操作定义。**纯算法可得，不需要用户自报、不新增题型。**
另允许用户**手动标「已在真实场景用过」**（可选，不作主要依据）。
`src:` X2

### SPEC-STEP-033 毕业后降频不退出
**裁定**：仍进复习队列，但间隔拉到年级别（`S` 继续增长，`due` 可能一年后才到）。**不假设永不遗忘** —— 真忘了仍会被 `Again` 拉回来。
`src:` X3

### SPEC-STEP-034 打卡项永不毕业
**裁定**：`S` 永不增长 ⇒ 永不到 180 ⇒ **打卡式项永远无法毕业**。它是学习痕迹，**不通往出口**。
**这是 M3 与 X2 相乘的必然结论，不是新增限制。必须显式写入规格** —— 不写清就会有人把它当 bug 修掉，一修就击穿 M3 的封顶逻辑。
`src:` V-5

| 裁定 | 可观测断言 | 测试向量 | 预期 |
|---|---|---|---|

| STEP-005 | 到点不切断进行中的项 | 预算剩 1 分钟时开始一项需 5 分钟的项 | 该项执行完才收尾，会话总时长 > 25 分钟 |
| STEP-009 | 游标不建表 | 检索 schema | 无 `SessionCursor` |

| STEP-011 | 回退不写事件 | 退到上一步再前进 | 事件数不变 |
| STEP-012 | 自创算子被拒 | `operator = "讨论"` | 校验失败，提示仅允许 6 类 |
| STEP-015 | 打卡项跳过 ⑤ | 判据为空的项跑完最后一步 | 直接写 `item_passed(checked)`，不出现题目 |

| STEP-021 | 连续两次未过判前置缺 | 同项连续两次未过（跨会话） | 生成缺口事件，项进缺口回补队列 |
| STEP-021 | 中间合格即清零 | 未过 → 合格 → 未过 | 不判前置缺（`failCount` 已清零） |
| STEP-022 | 用提示最高判合格 | 点开提示后答对 | `score` 最高为「合格」，「熟练」选项不可用 |
| STEP-024 | 跳过不写判定 | 跳过一项 | 事件流中无 `item_graded`，`failCount` 不变 |
| STEP-026 | 复习只跑 review 步骤 | 一个 5 步 profile（2 步标 first） | 复习只执行 3 步 |
| STEP-027 | 全 first 的 profile 被拒 | 所有步骤 `phase = first` | 校验失败 |
| STEP-032 | `S ≥ 180` 触发毕业 | `S = 179.9` → 复习后 `S = 185` | 写 `graduated` 事件 |
| STEP-034 | 打卡项不毕业 | 打卡项完成 100 次 | 无 `graduated` 事件；`S` 保持初值 |
