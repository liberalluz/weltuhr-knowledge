## 一、核心结论：进度与掌握是两套数据

### SPEC-QUANT-001 进度离散，掌握连续
**裁定**：

| | 进度 | 掌握度 |
|---|---|---|
| 形态 | **离散分数**：已学项数 / 圈内项数 | **连续值** `[0,1]` |
| 会回落吗 | **不会**（永不倒退） | **会**（可自由回落） |
| 用途 | 「还剩多少」 | 「学得多牢」 |

**两者是两套独立数据，不是同一个数的两种画法。** 混用会导致「复习没考好 → 进度倒退」这种荒谬表现。
`src:` M4 连带

### SPEC-QUANT-002 进度分母固定
**裁定**：分母 = **圈内项数**（含未纳入路径的游离项），**不随体系覆盖度变化**。分子 = 已学项数。
**因此**：换源、换体系、体系盖不满 `target`，都不改变分母。

**多设备不改变进度与掌握度**（补记，`B3` 笔 10）：分母是**项集合**，分子是「存在 `item_passed` 的项」，两者都按**项**计、不按**事件**计。所以同一项在两台设备各学一遍，进度不翻倍；掌握度是项的属性（`QUANT-004`），也不翻倍。[GOV-011](GOV-governance.md) 的「不去重、都重放」只影响事件条数，不进入本式。**推论**：任何按事件条数计的展示都不属于进度，见 [VIEW-035](VIEW-views.md)。

`src:` 第 29 轮 · N-1 / N-3

### SPEC-QUANT-003 已学门槛是事件，不是阈值
**裁定**：已学 = 存在 `item_passed` 事件（⑤ 首次验收合格；判据为空时 = 步骤跑完）。**事件性、不可撤销。**
**不用「掌握度 ≥ 0.5」** —— 掌握度会跌，跌了就「退回未学」，进度百分比会自己往下跳，分母也要跳。
`src:` M4 · V-6

## 二、掌握度公式

### SPEC-QUANT-004 `mastery = d × s`，两个维度
**裁定**：

```
d = 齐备要件格数 / 该类型可外化格总数      （深度）
s = S / (S + S₀)，S₀ = 30 天              （记忆强度，饱和归一）
mastery = d × s
```

**`score` 不在公式里。** `score` 是 `R` 的观测值，它已经通过 FSRS 更新了 `D`/`S` —— 再计入即**重复计分**。
`src:` 第 50 轮

### SPEC-QUANT-005 记忆强度用 `S`，不用 `R`
**裁定**：用 **`S`（稳定度）** 的饱和归一，不用当前可提取率 `R`。

| 用 `R` | 用 `S` |
|---|---|
| 时间一过 `R` 就自动下降 | `S` 只在未过时下跌 |
| **轨道环会自己变暗**，用户以为自己退步了 | 只在遗忘时真掉 |
| 与脉动通道重复表达同一件事 | 与脉动分工：环 = 多牢，脉动 = 该复习了 |

`R` 的职责是**判断何时复习**（脉动），不是**记录学得多好**（轨道环）。这是「一通道一维度」的直接应用。
`src:` M1

### SPEC-QUANT-006 深度分母扣除「不可外化」格
**裁定**：`d = 齐备格 ÷ 可外化格`。**「不可外化」不入分母。**

**若分母恒为 6**：语音项（几乎全格不可外化）与默会项的掌握度永久接近 0，而它们并不是没学会。这是对默会类知识的**系统性歧视**。
`src:` M2 · FND-004

### SPEC-QUANT-007 打卡式：照算但封顶 + 标未验证
**裁定**：打卡项照常算掌握度，但因**无检验输入**，`S` 只能从初学的初始值起步、不更新 ⇒ 掌握度自然偏低；UI 标「未验证」，**不假装与验证式同质**。
**不归零**：「我确实读了一小时」是弱证据，不该被当作没发生。
`src:` M3

### SPEC-QUANT-008 打卡封顶系数 = 0.5
**裁定**：封顶系数 `C-25` = **0.5**，作用为**乘积上限**：打卡式 `mastery = 0.5 × d × s`。

**为什么是乘积而不是取小**：`min(0.5, d × s)` 会把几乎所有打卡项压到同一个值，`d` 与 `s` 的差异全部消失 —— 那就不是「照算但封顶」，而是「一律记 0.5」，与 `SPEC-QUANT-007` 的「照算」和「不归零」同时冲突。乘系数保持单调，排序仍有效。

**为什么是 0.5**：与 `N-05`（打卡项永不毕业）同源 —— 无观测证据的项最多给「半可信」，不给出师资格。数值由决策人于 2026-10-17 裁定，**实施者不得改动**。
`src:` M3 · 用户裁定 2026-10-17

## 三、三层状态与毕业

### SPEC-QUANT-009 毕业只看 `S`，不看 `d`
**裁定**：毕业判据是 `S ≥ 180`，**不加 `d` 下限**。因此会出现「记得牢但学得浅」的毕业项（如 `d=0.5, S=180`，掌握度仅 43% 却已毕业）。

**这不是漏洞，是刻意**：出口问的是「能不能用」，与「懂多深」无关。「够用就行」是真实且正当的学习动机。
**处置**：能力清单里**同时显示掌握度**，让「学得浅」自己显现出来。
`src:` Y2

### SPEC-QUANT-010 毕业的视觉表达：轨道环加线型
**裁定**：轨道环**填充比例 = 掌握度**，**线型 = 毕业状态**（实线闭合 = 已毕业 / 虚线开口 = 未毕业）。
**这是全案唯一一次对「一通道一维度」的显式豁免**，理由与限制见 [`channel-table.md`](channel-table.md) §三。**不得作为先例。**
`src:` Y1

### SPEC-QUANT-011 能力清单是进展视图的一个分区
**裁定**：**不新增第六视图**。进展视图分两个分区：

| 分区 | 内容 |
|---|---|
| **计划进度** | 已完成段 + 当前循环轮次（不是单一线性百分比） |
| **能力清单** | 已毕业项 + 掌握度 + 适用场景 + **「历史」折叠区**（下线项） |

**理由**：底部导航承载 Z0–Z4 的**视距刻度**，加第六个视图会把它变成功能标签栏。
`src:` Y3 · Z4 连带

### SPEC-QUANT-012 能力清单复用定位引擎的反向查询
**裁定**：定位引擎问「我想学 X，它在哪」；能力清单问「我遇到 Y，我手上有什么能用」。**两者共用同一套索引（六轴 + 六要件 + `⪯`），只是查的方向相反。**
`src:` X4

## 四、进度模型的两个细节

### SPEC-QUANT-013 进度不是单一线性百分比
**裁定**：Planner ↔ Runner 是**交替循环**（可重规划），因此进度模型须是「**已完成段 + 当前循环轮次**」，不是一条直线百分比。重规划后要能**合并段**。
`src:` N-5 连带

### SPEC-QUANT-014 总览链的分段来自 `methodProfile`
**裁定**：一页总览链的**分段必须来自 `Plan.methodProfile`**，**不得硬编码七步**。否则用户建了四步方法，总览链画不出来、进度分母也对不上。
`src:` 第 43 轮连带

### SPEC-QUANT-015 进度可靠性两档
**裁定**：进度分 `verified`（有可观测判据）与 `checked`（判据为空）两档，**UI 必须能区分**，不能让两种进度用同一个百分比样式。
**判据**：方法本身**不标等级**（方法无权威谱系），但**进度有可信度差异** —— 给方法编等级是编的，给进度标「这条是打卡来的」是事实。
`src:` N-k · SF-1
